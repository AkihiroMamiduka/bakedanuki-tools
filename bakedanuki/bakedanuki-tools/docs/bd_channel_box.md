## 起動と終了

Maya上部の`bakedanuki > tools > bdChannelBox`から開けます。スクリプトから開く場合は
次を実行します。

```python
from bd_tools import bd_channel_box

window = bd_channel_box.show()
bd_channel_box.close()
```

`show()` は既存Windowを再利用します。importだけでは表示やscene変更を行いません。
開いた状態で`bd_tools.reload_package()`を実行すると、新しいWindowが自動表示されます。
閉じた状態なら表示されません。utilも更新した場合は
`bd_tools.reload_package(reload_util=True)`を使用します。
初回はMaya右側へドッキングします。タイトル部分をドラッグして、他の領域への移動、
タブ化、floatingへ切り替えられます。移動だけでは入力やstep設定を破棄しません。
配置はMayaのworkspaceへ保存され、再表示やMaya再起動時の復元に使われます。
本変更に対応した `bakedanuki-util` と組み合わせて使用してください。

利用するutilには、複数属性用の`MayaBoolPlugsBinding` / `MayaFloatPlugsBinding`、
`MayaIntPlugsBinding`、`MayaEnumPlugsBinding`、`MayaStringPlugsBinding`、
`IntValueStepSpinBox`、`IntSliderSpinBox`、`IntStepProfile`、
`EnumComboBox`、`StringLineEdit`、
`read_enum_definition()`、enum・string対応の属性列挙、
属性列挙・選択取得、`BoolCheckBox`、`FloatValueStepSpinBox`の幅指定、
`FloatSliderSpinBox.layout_order`、`MayaChannelStateBinding`、`MayaEditSession`、
`RadioButtonSweep` / `CheckBoxSweep`、`apply_plugs_values()`と
`MayaFloatValueEdit` / `MayaBoolValueEdit` / `MayaEnumValueEdit` /
`MayaStringValueEdit` / `MayaIntValueEdit` / `MayaIntOffsetEdit`、
整数Slider選別用の`MayaIntPlugsBinding.hard_limits`、接続属性編集の`edit_connected`引数と
`MayaPlugTargetState.edit_description`、`connected_plug_edit_reason()`、
時刻変更による操作終了の`FloatSlider.finish_edit()`、
ドッキングとreloadの基盤が必要です。
toolsとutilを配布するときは、組み合わせて動作確認した版を使用してください。

タイトルバーまたは `close()` で、workspaceControl・入力・callbackを破棄します。
次の `show()` は新しいWindowを生成します。開発時の完全破棄には `dispose()` を使います。
Escapeは値欄やメニューの操作に使い、パネル全体は閉じません。

配置を初期状態へ戻す場合は、次を実行します。

```python
window = bd_channel_box.reset_layout()
```

固定workspaceControl名は `bd_channel_box.WORKSPACE_CONTROL_NAME`
（`bdChannelBoxWindowWorkspaceControl`）です。
MayaのuiScriptは `bd_tools.bd_channel_box.ui.restore()` を呼び、復元中のcontrolへ内容を接続します。
`restore()` は通常の起動用ではなくMayaの復元処理専用です。
再起動後もtoolsとutilをimportできるよう、Maya.envまたはmodule pathの設定が必要です。

初回は右側へ配置し、以降はMayaが保存したworkspace配置を使います。
`reset_layout()` はworkspaceControlの保存配置をutilの統合APIで消去します。

## 表示と入力

- 一覧の余白・属性名・入力部品の周囲は、Maya UIの通常背景色を使います。
  数値・Stepなどの入力欄は暗い背景を保ち、入力箇所を区別します。
  boolのOFF表示も通常背景上に描画し、選択中は属性名だけを青く強調します。
  属性名の右側には4pxの内側余白を設け、選択色と文字の間隔を保ちます。
  値編集では属性名と入力Viewの間に6pxの接続状態表示を置き、外側の隙間は設けません。
  入力View内部の各欄は6px間隔で表示します。
  値・Step・Slider・bool・enum・stringの入力部品は、属性選択によって配色を変更しません。
  選択色や入力部品の色番号は固定せず、現在のQt paletteを使用します。
  状態表示は入力接続かロックがある場合にMaya標準Channel Boxに合わせた固定RGB色です。
- 上部の`Mode:`にあるComboBoxで、先頭から「値編集」「表示・ロック」「カスタムフィルター設定」を
  切り替えます。初回は値編集です。
  モードは開いているWindow内だけで保持し、scene・設定ファイルへ保存しません。
  切替だけでは属性の値・状態・Undo履歴を変更しません。
- その下の`Attribute Filter:`にあるComboBoxで表示対象を絞り込みます。
  値編集・表示ロックでは5種類の標準フィルターと、登録したカスタムフィルターを利用できます。
  カスタムフィルター設定では標準5種類だけを候補属性の絞り込みに利用できます。
  初期値は値編集が「keyable + channelbox」、表示・ロックが「全て」です。
  最後に選んだフィルターをモードごとに保持し、選択ノードの変更や表示更新でも維持します。
  値編集の選択は個人設定に保存して次回起動時も復元し、ほかのモードは再表示で初期値へ戻ります。
  ModeとAttribute Filterの2行は全モード共通のヘッダーとし、直下のフラットな横線で内容領域を区切ります。
  横線は「移動・回転をセット（子を維持）」と同じ表示に揃えます。
  検索欄の有無やモード切替では横位置・幅を変えず、Windowのリサイズにだけ追従します。
- `Attribute Search:`はNice Name・属性名・正式pathを検索します。初期状態では
  Attribute Filterが「全て」の場合だけ表示し、検索文字列はWindow内だけで保持します。
- 対象objectを抽出した現在のMaya active selection listの末尾ノードが基準です。
  画面上部の名前欄では、複数選択中も基準ノードだけを改名します。
  属性編集の対象ノードが2個以上なら、名前欄の右に「2 ノード」などの件数を表示します。
  未選択・1ノード選択では件数を表示しません。component・plugは数えません。
  選択数と選択順の全path、末尾が基準であることを名前欄と件数表示のtooltipへまとめます。
  範囲選択やスクリプトによる選択も現在のリスト順に従います。クリック履歴を記録する
  Mayaの設定は変更せず、厳密なクリック履歴順を独自に追跡しません。
- 名前欄はutilの`MayaNodeNameBinding`と`StringLineEdit`を使用します。
  bdChannelBox内では閲覧中に背景を周囲のpaletteへ合わせて枠を隠し、
  編集可能なフォーカス中は従来の入力欄の外観へ戻します。Enter確定後もフォーカス中は
  入力外観を保ちます。競合する下書きはフォーカスを失っても入力外観を保ち、
  読み取り専用時はフォーカス中も閲覧外観でコピーできます。
  初回のマウスフォーカスでは名前全体を選択し、フォーカス中の再クリックでは通常の
  カーソル移動に戻ります。
  Enter・テンキーEnter・通常のフォーカス移動で確定し、Escapeで未確定入力を破棄します。
  名前の衝突はMayaに委ね、採番後の確定名を表示します。通常の改名とUndo／Redoにも追従します。
  入力する名前は現在のnamespace内に限定し、transformに付くShape名の追従はMaya標準に従います。
  外部改名が編集中に起きた場合は入力を保持して競合を通知し、通常のフォーカス移動では
  上書きしません。Enterで明示的に確定できます。
  選択が変わると旧ノードへの未確定入力を破棄します。未選択時は案内文を表示し、
  参照ノードや名前ロック中はコピー可能な読み取り専用欄にします。
  名前欄の右クリックは文字列編集メニューです。属性行の右クリック操作は改名後の名前へ追従します。
- Maya nodeのobject選択が対象です。componentとplug選択は除外し、Shapeや履歴を
  自動で追加しません。DAG instanceの重複選択は同じnodeへまとめます。
  重複時は従来どおり最初のpathを残し、その抽出結果の末尾を基準にします。
  networkなどのDG nodeも従来どおり対象に含み、transformと混在しても末尾なら基準にします。
- どのモードも選択数の上限を設けません。「値編集」「表示・ロック」は選択全体を保持し、
  選択数によらず基準ノードだけを表示・監視します。
  基準以外の属性・値は操作時に取得します。具体的な違いは
  [値編集の対象構築](#値編集の対象構築)を参照してください。
- 「カスタムフィルター設定」もこの上限を設けず、基準一個だけを設定用の見本として
  保持します。属性・識別情報の取得と構成監視も基準だけに限定します。
  Mayaの選択は変更せず、値編集へ戻ると現在の全選択を操作対象として取得し直します。
- 基準nodeでフィルターに一致する対応scalarを、下記の優先順で表示します。
  XYZは子ごとに表示し、compound親の表示フラグでは子を除外しません。
  標準Channel Boxの表示順とは独立し、scene内の属性順は変更しません。
- 「全て」では非表示の属性も含めて列挙します。
  以前の操作や別ツールでHideにした属性も復帰できます。標準nodeの内部属性も含むため、
  表示される行数が増えます。値編集でも「全て」「hide」を選べば非表示属性へ入力できます。
  ロック中や未対応の入力接続を持つ属性の値を変更できない制限は維持します。
- bool、byte／short／long、float/double、距離、角度、enum、単一typed stringに対応します。
  対応するcompound子も対象です。int64、time、配列とその配下、compound全体は対象外です。
  整数欄は明示された両側hard limitがあれば`[値][Slider]`、それ以外は`[値][Step]`です。
  値欄の既定増減幅は1、Step欄は10倍方式です。
  型固有の範囲と属性のhard limitを検証します。
  時間カーブとSDK、short／longのAnimation Layerも既存型と同じ方針で編集します。
  Maya標準ではbyte属性をLayerへ登録できません。Enterは欄内で処理し、
  初回の文字クリックでは全選択します。再クリックとドラッグ選択は維持します。
- 同じ正式属性pathと型・単位種別の属性へ絶対値を一括入力します。
  距離と角度は同名でも対応付けません。編集対象数、対応しないnodeや編集不可の理由は
  属性名と入力Viewのtooltipへ表示します。属性のないnodeへ属性を追加することはありません。

標準フィルターは基準ノードの現在のplug状態で判定します。
基準以外のノードの表示状態が異なっても、同名・同種の属性は一括編集の対象に含めます。
たとえばjointの`.otherType`は通常の表示フラグに従い、既定の値編集フィルターには
現れません。「全て」または「hide」を選び、必要なら`otherType`を検索してください。
Windowの起動時に表示フラグや値を変更しません。

| フィルター | 基準属性の条件 |
| --- | --- |
| 全て | 表示状態による除外なし |
| keyable + channelbox | keyableまたはchannelBoxがTrue |
| keyable | keyableがTrue（channelBoxもTrueならこちらに分類） |
| channelbox | keyableがFalse、channelBoxがTrue |
| hide | keyableもchannelBoxもFalse |

状態を変更して標準フィルターの条件から外れた行は、複数対象への操作が完了してから消えます。
ラジオボタンをなぞっている間は行を維持し、マウスを離した後にまとめて絞り込みます。
「全て」を選ぶと再び表示でき、Undo／Redoや外部での状態変更にも表示が追従します。
フィルター切替だけではscene・Undo履歴を変更しません。

### カスタムフィルター

「プリセットグループ → プリセット → カスタムフィルター」の3段階で共有JSONを登録します。
グループはプリセットの一覧と順序、プリセットはフィルターの一覧・順序・表示ON/OFFを保持します。
用途は固定しておらず、任意の名前で整理できます。全Mode共通の「プリセット」行で一覧を切り替えます。
設定Modeでは同じ行を「編集するプリセット」とし、新規作成・リネームのアイコンを表示します。
上位グループの切替と登録は「設定」→「カスタムフィルター管理」で行います。
現在のグループ名はプリセット選択欄のtooltipで確認できます。

グループ・プリセット・フィルターの名前はすべて、実ファイル名から`.json`を除いた文字列です。
別の表示名はJSONに保存しません。同名の別ファイルはパスで区別します。
同じフィルターJSONを複数プリセットから参照でき、登録順とON/OFFはプリセットごとに独立します。
属性定義の編集は同じJSONを参照しているすべてのプリセットに共通です。
同じプリセットJSONを複数グループから参照した場合は、そのフィルター一覧も共有します。
独立した構成や属性定義が必要な場合は、該当するファイルを「複製」します。
グループ・プリセットの複製は保存済みの参照一覧だけを別JSONへコピーし、下位のJSONは
複製しません。複製後も参照先は共有するため、独立した属性定義が必要ならフィルターも複製します。
参照パスは参照元JSONを基準に保存し、関連フォルダーの構成を保って移動・共有できます。
大小文字だけの改名はWindowsで扱えますが、参照元の表記は残る場合があります。
大小文字を区別するファイルシステムへ共有する場合は、参照パスの表記も合わせてください。

グループJSONは次の形式です。配列の順序がプリセットの表示順になります。

```json
{
  "schema_version": 1,
  "presets": ["../preset/Modeling.json", "../preset/Rigging.json"]
}
```

プリセットJSONは次の形式です。`enabled`はそのプリセットだけの表示ON/OFFです。
別ドライブのファイルは相対化できないため、絶対パスで保存します。

```json
{
  "schema_version": 1,
  "filters": [
    {"path": "../filter/Transform.json", "enabled": true},
    {"path": "../filter/Controls.json", "enabled": false}
  ]
}
```

設定メニューと設定Mode共通操作の歯車は、どちらも操作時のカーソル位置を中央の基準にして
同じ管理ウィンドウを表示します。既に開いている場合も、その位置付近へ移動して前面に出します。
操作したモニターのタスクバーなどを除く作業領域へ、タイトルバー・外枠まで収めます。
利用者が変更したサイズは保ち、画面より大きい場合だけ収まる寸法へ縮小します。
閉じてから再表示する場合も今回の操作位置を使い、行選択・現在行・表示設定は維持します。
管理画面はグループ・プリセット・フィルターの縦3段で、段の間をドラッグして高さを調整できます。
どの段もCtrl／Shiftで複数選択でき、削除・上下移動は選択全件を対象にします。
現在行が、次の段に表示する対象です。複数選択した親の内容は合算しません。
選択が0件の段では、その下の一覧を空にします。
各段では新規作成・追加・複製・リネーム・登録削除・上下の並べ替えを行います。
最下段では目のON/OFFも変更できます。削除は所属・登録だけを外し、参照先JSONは残します。
保存・破棄・全て再読込は全体の操作です。
「目のアイコンで Attribute Filter への表示を切り替えます」の説明と一覧の間に、
新規作成・追加・複製・リネーム・登録から削除・上へ・下へを、この順に左寄せで並べます。
ボタンは20×20、アイコンは16×16で、操作名はtooltipから確認できます。
アイコンは順に`fileNew.png`・`item_add.png`・`polyCopyUV.png`・`fileTextureEdit.png`・
`RS_delete.png`・`nodeGrapherArrowUp.png`・`nodeGrapherArrowDown.png`を使用します。
全体の保存・破棄・再読込は上部へ置き、`fileSave.png`・`redo_s.png`・`UVTkRotateCW.png`を使用します。
一覧は階層のないQTreeWidgetで、フィルター名・ファイルパス・読込状態の3列を表示します。
名前と読込状態は内容に合わせた幅にし、ファイルパスは残りの幅いっぱいに広げます。
Windowの拡縮にもファイルパス列が追従します。登録順を保つため、列見出しでのソートは行いません。
長いファイルパスは左側を「…」で省略し、末尾のファイル名を優先して表示します。
パス全文と読込エラーの理由は、各行のtooltipで確認できます。
「読込済み」は最後にJSONを正常に読み込み・検証できた状態を示し、表示のON/OFFや
設定モードの未保存変更とは独立しています。ファイル消失や不正なJSONは「読込エラー」と表示します。
通常のファイル詳細ラベルは下部に置かず、登録設定そのものの読込・保存エラーだけを別途表示します。

行はCtrl／Shiftで複数選択できます。名前左の目のアイコンはAttribute Filterへの表示を切り替え、
行選択はボタンの操作対象を決めます。ONは`ghostingVisible.png`、OFFは`ghostingHidden.png`を
16×16で表示し、約20×20のフラットな領域をクリックして切り替えます。
選択内の目をクリックすると、クリック行がONなら選択全件をOFF、OFFなら全件をONに揃えます。
ON／OFFが混在していても同じ規則です。選択外の目はその1件だけを切り替えます。
既存の複数選択と現在行は維持します。名前・行の余白は通常どおり行選択に使用できます。
管理画面の一覧・操作ボタンではSpaceによる行選択・表示切替・ボタン押下を行いません。
Spaceの入力はMayaへ受け流し、標準割当では長押しでHotboxが表示され、解放すると閉じます。
矢印・Tabなどのキー操作や、作成・名前変更などで開く別ダイアログの入力は通常どおりです。
tooltipにはAttribute Filterへの表示ON/OFFと対象件数・切替後の状態を表示します。
表示設定とJSONの読込状態は独立しており、読込エラーは引き続き状態列で確認できます。
削除は選択した登録をまとめて外し、JSONファイルを残します。
上下移動は選択行同士の相対順を保ち、全選択行を1段ずつ移動します。
先頭行を含む選択では「上へ」、末尾行を含む選択では「下へ」を無効にします。
「複製」は正常に読み込めた1件だけを選択した場合に有効です。
個別の再読込ボタンは設けず、「全て再読込」でOFFや読込エラーの登録も含めて更新します。
再読込・上下移動・表示切替の操作では、残っている登録の行選択とcurrentを維持します。
全て再読込は登録順とON/OFFも維持します。
「新規作成...」で保存先とファイル名を指定すると、空の有効なJSONを作成して登録一覧の末尾に
ONで追加します。管理画面を開いたまま作成行を選択し、カスタムフィルター設定モードの
編集対象にも反映します。既存ファイルは上書きしません。
新規作成・追加のダイアログは、操作した段の選択中の現在行のJSONが入っているフォルダーを開きます。
複数選択中も現在行を基準にし、読込エラーのJSONでも親フォルダーが存在すれば使用します。
設定Modeの新規作成も、編集中のプリセット・フィルターのフォルダーを使います。
未選択、または親フォルダーが存在しない場合は、使用中Mayaのprefsにある
`bakedanuki/tools/bd_channel_box/custom_filter/`配下の種類別フォルダーを開きます。
グループは`preset_group/`、プリセットは`preset/`、フィルターは`filter/`です。
必要なprefsフォルダーを作成し、消失した共有先は再作成しません。
新規作成のファイル名は空欄から入力します。任意の保存先への変更も可能です。
未保存確認・エラー通知・既存JSONの追加・作成・複製・名前変更の画面は、
操作開始時のカーソル位置を中心に表示します。
クリックしたモニターの作業領域へタイトルバー・外枠まで収め、必要な場合だけ縮小します。
未保存確認を挟んでも最初の操作位置を使い、Qt標準の上書き確認も同じ起点へ配置します。
キーボード操作では、操作元のフォーカス部品付近へ表示します。
追加・保存画面には位置を制御できるQt版を使用するため、Windows標準とは見た目が変わります。
表示後に手で移動した画面をカーソルへ追従させることはありません。
bdChannelBox本体と、右クリックから開く子補償・回転姿勢維持Windowは保存配置を優先します。
名前入力は保存ダイアログに一本化し、選んだファイル名から`.json`を除いた文字列を表示名にします。
既存ファイルを指定した場合は作成せず、保存先を選び直せます。
「複製...」は「追加...」と「削除」の間にあり、選択した正常なJSONの全ノード型・
属性順・0件の型定義を引き継いで別ファイルへ保存します。OFFの登録も複製できます。
保存先の初期名は`元の名前_copy.json`、初期フォルダーは元JSONのフォルダーです。
複製も保存ダイアログで選んだファイル名を表示名に使います。
複製後は末尾へONで登録し、管理画面を開いたまま複製行を選択して、設定モードの編集対象にします。
既存ファイルは上書きしません。
新規作成・複製の前に未保存変更の保存・破棄・キャンセルを確認します。
キャンセルした場合は新しいファイルや登録を作成しません。
有効で正常に読み込めたファイルだけを`Attribute Filter:`の標準5項目の末尾へ
`Custom: Rig`のように表示し、管理画面の登録順を保ちます。
OFFにしたファイルは登録位置を保ったまま一覧から一時的に除外します。
選択中のファイルをOFF・削除した場合は、そのモードの初期フィルターへ戻ります。

1ファイルで1フィルターを定義し、共有先に置いたまま参照します。
グループ・プリセットの構成変更と編集中の属性定義は、共通の「保存」で確定します。
「元に戻す」は未保存の構成と属性編集をまとめて破棄します。
新規作成・複製の保存ダイアログで作成済みのJSONは、破棄しても物理削除しません。
グループ登録と最後の選択は各ユーザーの設定で保持し、選択の切替だけでは未保存扱いにしません。
旧版の登録一覧は最初のグループ・プリセットへ引き継ぎ、旧フィルターJSONを移動しません。
Window再表示、package reload、配置reset、Maya再起動後にも登録が残ります。
値編集モードで最後に選んだAttribute FilterもMaya version別の個人設定へ自動保存し、
次回起動時に復元します。標準項目は固定の識別子、カスタムはJSONのpathで記憶するため、
表示名の変更や登録順の並べ替えに影響されません。OFF・登録削除・読込不能で復元できない
場合と、保存値が未設定・不正な場合は`keyable + channelbox`へ戻します。
JSONに現在ノード型の定義がない場合はカスタム選択を保ち、表示条件だけ標準へ切り替えます。
表示・ロックと設定モードのフィルター選択、Mode自体と検索文字列はWindow内だけで保持し、
それらのモードを開いたまま終了しても値編集用の保存値を上書きしません。

```json
{
  "schema_version": 2,
  "node_types": {
    "transform": [
      "visibility",
      "translate.translateX",
      "rigMode"
    ],
    "joint": [
      "visibility",
      "jointOrient.jointOrientX",
      "jointOrient.jointOrientY"
    ]
  }
}
```

例えば`Rig.json`は`Custom: Rig`と表示します。`node_types`のキーはMayaが返すノード型名と
完全一致で照合し、親型の定義を継承しません。属性はalias・短名・ノード名を含めず、
`translate.translateX`のように親を含む正式な相対pathで指定します。
`schema_version`は整数の`2`です。旧形式の`1`も読み込めますが、表示にはファイル名を使います。
既存JSONは読込時には書き換えず、明示保存したときに`name`のないversion 2へ更新します。
version 2を読む環境も、対応するtoolsへ更新してください。
同じ配列に重複するpathは最初の指定だけ使います。
各ノード型の配列に書いた順番が属性行の表示順です。現在のplugがKeyable・
ChannelBox・Hiddenのどれでも、指定した対応scalar属性を表示します。
存在しない属性や未対応の型はそのノードでは表示しません。JSONにそのノード型の
定義がない場合だけ、Keyable + ChannelBoxの標準条件へ切り替えます。
切替中は`Attribute Filter:`の下に基準ノード型と適用中の条件を表示します。
定義はあるが属性が見つからない場合や配列が空の場合は空のままにし、
暗黙の切替で定義ミスを隠しません。

複数選択では末尾の基準ノードの型とJSON定義で行を決めます。他のノードは従来どおり
型を問わず同じ正式pathと値種別の属性を一括編集の対象に含めます。
ロックや未対応の入力接続による編集制限は変えません。
ファイルを編集したら管理画面の再読込で反映します。ファイルが見つからない場合や
JSONが不正な場合は登録を残してエラーを表示し、修正後に再読込できます。
カスタムフィルターの追加・切替はsceneとUndo履歴を変更しません。
値を揃える操作と貼り付け操作の表示状態フィルターは従来の標準5種類です。
表示状態を変更しても、JSONの指定があるカスタムフィルターの行は残ります。

#### 共有用エクスポート

管理画面の各段の右端にある`UVTkNudgeUp.png`のボタンから、共有するJSON一式を出力できます。
既存の操作アイコンとは伸縮する余白を挟み、ウィンドウを広げても右端に配置します。

| 段 | 選択条件 | 出力範囲 |
| --- | --- | --- |
| プリセットグループ | 正常な行を1件 | そのグループと、配下の全プリセット・フィルター |
| プリセット | 正常な行を1件 | そのプリセットと、配下の全フィルター |
| カスタムフィルター | 正常な行を1件以上 | 選択した全フィルター |

未選択、上位2段の複数選択、選択に読込エラーを含む場合は無効です。
選択解除後に残る現在行だけを出力対象にはしません。

出力対象は保存済みの内容です。構成や属性に未保存変更がある場合は、
「保存してエクスポート」「キャンセル」で確認します。キャンセルは編集内容を保持し、
保存失敗時も保存先選択や出力へ進みません。保存で改名した場合は、改名後の同じ対象を出力します。
保存先の選択を取り消した場合、既に保存した編集内容は保存済みのままです。

保存先選択はMaya標準のフォルダーブラウザーです。上部の`Look In:`へパスを貼り付けて
Enterで移動し、現在のフルパスを選択・コピーできます。下部の`Directory:`は選択の確定に使います。
初期サイズは`bd_channel_box/config.py`の次の2値だけで調整します。

```python
EXPORT_DIRECTORY_DIALOG_WIDTH: int = 1200
EXPORT_DIRECTORY_DIALOG_HEIGHT: int = 650
```

幅・高さはQtの論理ピクセルで直接指定し、変更後は`bd_tools.reload_package()`で読み直します。
画面より大きい場合は作業領域へ収めます。表示後の手動リサイズ・移動も可能です。

選択した保存先の中へ、次の構成で出力します。出力するファイルがない種類のフォルダーは作りません。

```text
export_custom_filter/
  preset_group/
  preset/
  filter/
```

同名の出力フォルダーが存在する場合は`export_custom_filter_001`のように連番を付けます。
参照先は表示OFFのフィルターも含めて出力し、登録順とON/OFFを維持します。
同じファイルへの共有参照は1回のコピーにまとめ、別の場所にある同名JSONは出力側の名前を調整します。
グループ・プリセットの参照を出力先の相対パスへ書き換えるため、
エクスポートフォルダー全体を移動・受け渡ししても、その中だけで参照できます。
受け取った側では、含まれるグループ・プリセット・フィルターを管理画面の「追加」から登録できます。

必要な参照先の消失・不正なJSON・書込み失敗は全体のエラーとして通知します。
必要なファイルを検証してから一時フォルダーへ作成し、完成した一式だけを公開します。
既存の出力と元のJSONを上書きしません。確認・保存先選択・通知は最初の操作位置を引き継ぎます。

#### カスタムフィルター設定モード

Modeを「カスタムフィルター設定」にすると、選択末尾の基準ノードにある対応scalar属性を
候補として表示します。選択数の上限はなく、異なる型を含む多数選択でも基準一個だけから
候補を取得します。画面の「基準: ノード名（型）」で編集する型を示します。
基準は見本であり、保存先は個別ノードではなく、その型全体に使う共有JSONの定義です。
基準を切り替えても別の型の定義と未保存データを保持します。
Attribute Filterは標準5種類だけで、初期値は「全て」です。
このモードでは画面の余白やウィジェットを右クリックしても「Step設定」を開きません。
「編集するフィルター」で登録済みの正常なJSONを選びます。管理画面でOFFにした定義も
編集できます。ComboBox右隣の`fileNew.png`の新規作成アイコン（20×20）からも名前と
保存先を指定して新規JSONを作成・登録でき、管理画面を開かずに編集を始められます。
tooltipは「カスタムフィルターを新規作成」です。
プリセット行とフィルター行の右端には、それぞれ新規作成・名前変更を並べます。
その上に全体の保存・破棄・管理を、この順に右寄せで並べます。各ボタンは20×20で、
新規は`fileNew.png`、改名は`fileTextureEdit.png`、保存は`fileSave.png`、
破棄は`redo_s.png`、管理は`QR_settings.png`です。
保存・破棄は未保存の変更がある場合だけ有効です。管理はフィルター未選択でも使用でき、
tooltipは「カスタムフィルター管理」です。上部メニューと同じウィンドウを再利用して開き、
編集中の内容・検索・ページを保持します。
常設の表示名入力欄は設けず、名前変更ダイアログに現在の名前を表示します。
名前変更は同じフォルダー内のJSONファイル名を変更します。入力中に空欄・不正な
ファイル名・既存の別ファイルとの衝突を検査し、説明文を表示してOKを無効にします。
確定後は編集用ComboBoxへ新名と未保存印`*`を反映し、保存前は元ファイルを維持します。
保存ボタンで全構成と属性編集を確定し、登録順・ON/OFF・各モードの選択と値編集の
保存済み選択を新pathへ引き継ぎます。破棄した場合は元の名前とpathに戻ります。
保存直前に作成された別ファイルも上書きせず、未保存内容を保持して通知します。
既存JSONを読み込んだだけでは改名しません。同名の項目はファイル名、必要ならフォルダーを
補足表示し、tooltipで定義のpathを確認できます。
改名時は登録済みグループから到達する参照元も更新します。
既知の参照元の読込・書込・外部変更に問題がある場合は、改名を確定しません。
未登録のJSONや別環境のコピーは追跡できないため、関連ファイルを改めて共有してください。
破棄ボタンのtooltipは「保存済みの内容に戻す（変更を破棄）」です。
候補の「含める」「含めない」はJSONへの所属だけを変更し、Mayaの
keyable・channelBox・lock・値、sceneとUndo履歴には触れません。

「基準:」の直上にある「編集するノード型」は、先頭の「選択ノード」と編集中JSONの
型名を列挙します。未保存で追加した型と属性0件の型も含みます。「選択ノード」は従来の
選択末尾へ追従し、型名を直接選ぶとMayaの選択に関係なくその型を編集します。
型の切替では全型の未保存内容を保持し、候補と表示順の選択だけを解除します。
型の定義を削除して選択項目がなくなった場合は「選択ノード」へ戻ります。
「基準: ノード名・型」の表示は維持し、その下の常設案内・件数ラベルは設けません。
未保存状態は編集用ComboBoxの`*`で示し、型情報の取得失敗と保存失敗は共通通知欄へ表示します。

型の直接選択では、ノードを作成せずに型の標準属性と保存済みpathを候補にします。
標準Attribute Filterは型既定のkeyable・channelBoxフラグを使います。型から情報を
取得できない保存済みpathは「保存済み・型情報未確認」と注記し、「全て」の場合だけ
候補に表示します。除外後も同じ編集中は候補に残るため再追加できます。
未ロードplug-inの型でも既存定義を整理できます。個別ノードに追加された未登録属性は
「選択ノード」から取得してください。実ノードの表示フラグ変更は型の既定値へ影響しません。

追加した属性pathは定義配列の末尾に入り、「フィルターの表示順」の一覧左側に縦配置した
20×20の「上へ」「下へ」「除外」アイコンで操作します。tooltipにも操作名を表示します。
上下は`nodeGrapherArrowUp.png`・`nodeGrapherArrowDown.png`を優先し、取得できない環境では
`arrowUp.png`・`arrowDown.png`を使います。除外は`RS_delete.png`です。
現在の候補にない既存pathも順序一覧に残ります。
上段の一覧は通常クリックで1件、Ctrlクリックで個別の追加・解除、Shiftクリックで
連続範囲を選択できます。「上へ」「下へ」は選択全件を同時に一段動かし、選択属性同士の
順番と離れた選択の間隔を保ちます。先頭を含む場合の「上へ」と末尾を含む場合の「下へ」は
無効です。移動後も同じ属性の選択を維持します。「除外」は上段の選択全件を対象にし、
現在のノードにないpathも消せます。下段の候補選択は対象に含めず、別のノード型の定義も
変更しません。編集対象JSONや基準ノードを切り替えると上段の選択を解除します。
一覧の項目上で右クリックすると、ゴミ箱ボタンと同じ「除外する」を表示します。
選択中の行では複数選択を保ち、選択外の行ではその1行だけを選択してから開きます。
余白・空一覧では選択を保ったままメニューを表示しません。除外は下書きだけを変更し、
共有JSONは保存ボタンで確定します。保存前なら破棄でき、Mayaの属性は削除しません。
未保存の追加をすべて除外した場合は元の型未定義へ戻り、既存の明示定義からすべて
除外した場合は空配列を保ちます。
「フィルターの表示順」と「属性をフィルターに含める」はQToolBoxの見出しをクリックして
切り替え、選んだページへ作業領域を配分します。初回は属性候補を開き、その後はWindow内で
開いたページを保持します。フィルター・型の選択や保存操作はページ外の共通領域に置きます。
ページ切替では未保存内容・検索文字列・各一覧の選択とスクロール位置を保持します。
ページと候補領域の背景はMayaの通常のウィンドウ配色を引き継ぎ、固定色は使いません。
「属性検索」は候補一覧の直上に配置します。候補全件の含める／含めない専用ボタンは
設けず、複数選択した候補へのラジオ操作でまとめて所属を変更します。
設定モードの属性検索欄は標準の右クリックメニューを表示せず、親のメニューも開きません。
文字入力とCtrl+C／X／V／Zによるコピー・切り取り・貼り付け・Undoは維持します。
候補のラジオで属性をすべて除外して0件になった型は空配列を保ちます。
所属変更はJSONの作業中データだけを変更し、sceneとUndo履歴には触れません。
候補の属性名をクリックすると1件を選択し、Ctrlクリックで離れた属性を追加・解除、
Shiftクリックまたは属性名からの縦ドラッグで連続範囲を選択します。候補一覧の余白を
クリックすると選択を解除します。
ラジオを縦になぞると開始した「含める」または「含めない」の列の通過行だけへ適用します。
属性の選択集合は保ち、選択中の離れた行には波及しません。同じ行は一ドラッグで一回だけ
処理し、新規の含める属性は通過順に追加します。radioはその場で同期し、表示順・状態表示の
更新は終了時にまとめます。別列へ動かしても操作の種類は切り替わりません。
選択中の行の「含める」「含めない」を押すと、選択属性すべてに適用します。
選択外の行のラジオはその1件だけに適用し、既存の選択を維持します。ラジオのtooltipは
現在の適用範囲を示します。既にONのラジオを押しても、別の選択属性に同じ状態を適用できます。
すべて既に同じ状態なら変更しません。上段の表示順一覧の操作は下段の複数選択には
適用しません。
選択はスクロール位置が変わっても残り、検索・標準Attribute Filterで隠れた候補は
選択から外れます。基準ノードや編集対象JSONを切り替えると選択を解除します。
選択操作自体はJSONやsceneを変更せず、複数行の追加は候補の表示順でJSON配列の末尾へ
入ります。既存の属性順と候補外のpathは維持します。
ノード型を初めて編集するとその型の配列を作ります。「この型を0件で定義」専用ボタンは
設けませんが、既存JSONの空配列は引き続き有効で、その型では何も表示しません。
未定義型の`keyable + channelbox`表示へ戻す場合は、ノード型ComboBox右隣の
`RS_delete.png`のゴミ箱アイコン（20×20）を使います。型定義がある場合だけ有効で、
tooltipは「この型のフィルター定義を削除して標準表示に戻す」です。
その型の下書きだけを削除し、選択中の型の項目がなくなった場合は「選択ノード」へ戻ります。
Mayaのノード・属性は削除せず、保存前のJSONと別の型の定義にも触れません。

ファイル名・構成・属性・順序の編集は、共通の保存で確定します。
保存前にモード、編集中のフィルター、グループ・プリセットを切り替えると、
必要に応じて保存・破棄・キャンセルを選べます。型定義の削除も保存で確定し、
保存前なら変更を破棄できます。
保存時は共有JSONの外部変更を検出し、
変更されていた場合は上書きせず再読込を促します。保存後は登録定義を再読込し、通常モードの
Custom表示へ反映します。空の`"node_types": {}`も有効で、すべてのノード型が未定義型の
代替表示になります。既存JSONの形式変更は不要です。
ウィンドウやdockを閉じる、配置をresetする、packageをreloadする場合は未保存の
作業中データが破棄されます。これらの操作前に共通の保存ボタンを押してください。

保存・改名は変更対象の外部更新・宛先衝突・書込可否を先に検査し、途中の書込み失敗では

共有先の同時編集を拡張する場合は、既存の競合検出・復元テストを基準に保存方式を検討します。
改名に伴う参照修復は登録グループから到達する既知の文書が対象で、

### 属性検索

検索欄はNice Name・leaf属性名・`translate.translateX`などの正式属性pathを、
大文字小文字を区別せず部分一致で検索します。空白で区切った複数語はAND条件です。
正規表現とワイルドカードは解釈しません。検索は現在のAttribute Filterの結果へ追加で適用し、
属性の表示順は変更しません。

設定メニューの「検索欄の表示」では、次の3項目を排他的に選択します。

| 表示方針 | 動作 |
| --- | --- |
| 非表示 | Attribute Filterに関係なく検索欄を表示しない |
| 「全て」の場合のみ表示 | Attribute Filterが「全て」の場合だけ表示する。初期値 |
| 常に表示 | 標準とカスタムの全Attribute Filterで表示する |

初期設定の「全て」の場合のみ表示では、カスタムフィルター選択中の検索欄も隠れます。
カスタムフィルター内で検索したい場合は「常に表示」を選びます。

検索条件は検索欄が表示されている間だけ有効です。条件や設定によって検索欄が隠れた場合は、
入力済みの文字列をWindow内に保持したまま検索を停止し、Attribute Filterに該当する全行を表示します。
再表示すると保持した文字列を再適用します。検索文字列はモード・ノード選択・表示更新をまたいで
維持しますが、Windowの終了・reload・Maya再起動後は空から開始します。
表示方針だけを`bd_channel_box/preferences/main`へ保存し、Window再表示・Maya再起動後に
復元します。既存設定に項目がなければ「全て」の場合のみ表示から開始し、`reset_layout()`では削除しません。

検索で隠れた属性は選択から外し、検索を解除しても自動再選択しません。
表示されていない属性が値・状態・選択属性Copy/Pasteの対象へ残ることを防ぎます。
「全属性」Copyと「コピー元と同じ属性」Pasteは、従来どおり画面の表示行や検索に依存しません。
結果が0件の場合は、対応属性やAttribute Filterが0件の場合と区別して案内します。

検索ではMaya属性を再列挙せず、既に構築したQTableViewの行を表示・非表示にします。
既存の行Widget・Binding・callbackを維持し、scene・値・状態・Undo履歴を変更しません。
検索で行を隠す前に未確定の値入力と連続操作を終了します。

共通ヘッダーのラベルは右揃えにし、2つのComboBoxの左端・幅を揃えます。
Attribute Searchは仕切り線の下に独立して配置し、表示切替がヘッダー幅へ影響しないようにします。
パネルを広げた分は入力欄へ配分します。

次の属性表示優先順は、両モード・標準5フィルターで共通です。
存在し、フィルターに一致する属性を次の順で先頭へ配置します。

| 優先位置 | 属性（各行の左から順） |
| --- | --- |
| 1 | visibility |
| 2–4 | translateX, translateY, translateZ |
| 5–7 | rotateX, rotateY, rotateZ |
| 8–10 | scaleX, scaleY, scaleZ |
| 11–13 | jointOrientX, jointOrientY, jointOrientZ |
| 14 | rotateOrder |
| 15–17 | rotateAxisX, rotateAxisY, rotateAxisZ |
| 18–20 | shearXY, shearXZ, shearYZ |
| 21–23 | rotatePivotX, rotatePivotY, rotatePivotZ |
| 24–26 | rotatePivotTranslateX, rotatePivotTranslateY, rotatePivotTranslateZ |
| 27–29 | scalePivotX, scalePivotY, scalePivotZ |
| 30–32 | scalePivotTranslateX, scalePivotTranslateY, scalePivotTranslateZ |
| その後 | drawOverride配下の対応scalar |
| 最後 | その他の対応scalar |

`drawOverride`配下は有効化を操作する`overrideEnabled`を先頭にします。
残りは`overrideColorRGB`のR/G/B子も含め、元の相対順を保ちます。
byte型の`overrideColor`も表示し、その他の属性も元の相対順を保ちます。
表示名やleaf名ではなく、`translate.translateX`などの正式な属性pathで照合します。
別compound内の同名属性は優先対象に含めず、nodeの型による制限は設けません。
この順序は[config.py](../python/bd_tools/bd_channel_box/config.py)の
`ATTRIBUTE_PRIORITY_PATHS`で調整できます。上から優先したい順に文字列を並べ、
必要な属性の追加・削除もこのtupleだけで行います。存在しない属性は飛ばし、
重複したpathは最初の指定を採用します。
未指定属性は`drawOverride`配下、その他の順に並び、それぞれ元の相対順を保ちます。
既定の`drawOverride.overrideEnabled`の指定を残すと、同系統の先頭を維持できます。
並べ替えは行の構築時だけ行い、通常の値変更では再実行しません。

ファイルを編集・保存した後は、次のコードでtoolsを再読込みして開き直します。

```python
import bd_tools
bd_tools.reload_package()

from bd_tools import bd_channel_box
bd_channel_box.show()
```

Pythonから`bd_channel_box.config.ATTRIBUTE_PRIORITY_PATHS`を一時的に差し替える場合は、
現在のノード選択を一度解除し、同じ順序で選び直すと反映できます。
再読込み・Maya再起動後はファイル内の設定へ戻ります。
表示順だけを変更し、sceneの属性順・値・Undo履歴には書き込みません。

属性名は共通幅の列で右揃えにし、表示中の全行で入力欄の左端を揃えます。
入力グループは値編集が222 px、表示・ロックはボタンの必要幅に合わせます。
モード切替ではWindow幅を保ち、各モードの操作欄とスクロールバーに応じて名前列の幅を調整します。
初期サイズの指定は380×360、最小幅は340です。実際の寸法はMayaのドック領域に合わせて調整されます。
属性名側の余白は`ui.py`の`_INITIAL_WIDTH`・`_MINIMUM_WIDTH`で調整できます。
名前列の推奨幅は`widget.py`の`_NAME_FIELD_PREFERRED_WIDTH`（92 px）で指定します。
狭いパネルでは名前列を縮めて入力欄を確保します。
長い名前は省略表示し、正式な属性pathと省略していない表示名をtooltipへ表示します。
行数や名前の長さでWindow幅を広げず、縦スクロールバーは内容が収まらない場合だけ表示します。
その出入りに伴って、名前列の幅と入力欄の位置は変わります。
保存済みの広い配置を使っている場合は、パネル幅を縮めるか`reset_layout()`で初期配置へ戻します。

選択・初期表示・外部変更の同期・表示更新では値を書き込みません。
数値入力はEnterまたはフォーカス移動で確定し、値欄の上下操作・Sliderは操作時に反映します。
未編集のEnterやフォーカス移動も値を書き込みません。
数値の文字入力中に上部のモード・フィルターComboBoxへ移動した場合も、通常のフォーカス移動として
その編集を確定します。未編集の表示切替だけで値を揃えることはありません。
boolはutilの`BoolCheckBox`を使い、属性名のすぐ右、数値入力列の左端にチェックを表示します。
チェックまたはSpaceキーで切り替えると、対応する編集可能なノードへ一括適用します。
boolが混在していてもチェックは基準ノードのTrue / Falseを表示し、三状態表示にはしません。

enumはutilの`EnumComboBox`で項目名を表示します。入力列全体の222 pxを使い、
Step／Sliderは表示しません。標準属性（rotateOrderなど）も追加属性も同じ扱いですが、
他の型と同じフィルターで表示対象を決めます。
負数・飛び番を扱い、ComboBoxの位置ではなく定義の整数値を入力します。
tooltipには省略されていない基準の項目名と実整数も表示します。

enumの編集対象は、正式属性pathと型に加えて**整数値と項目名の対応**が一致するノードです。
定義の表示順だけの違いは許容します。初期表示・選択変更・行の再構築時に不一致の対象を
除外し、tooltipへ理由を表示します。項目名による値の変換や定義の書き換えは行いません。
Bindingへ登録した対象の定義が使用中に不一致になると、その行の入力を停止します。
定義が揃えば再開し、ノード選択を一度解除して選び直すと除外した対象も含めて
組み合わせを再判定します。除外済みの対象を定義修正後に戻す場合も同様です。

現在値が選択肢に含まれない場合は`未定義 (5)`などと表示し、値を自動修正しません。
有効な項目への変更は可能ですが、その属性だけを選んだ
「表示ノードの値に揃える > 選択属性」は無効になります。
複数属性を揃える操作では、その未定義の行を対象から除外します。
選択肢が空なら入力も無効です。ComboBoxで同じ項目を選び直すだけでは書き込まず、
混在した値を表示中の項目へ揃える場合は
「表示ノードの値に揃える > 選択属性」を使います。

stringはutilの`StringLineEdit`で一行入力します。入力列全体の222 pxを使い、
Step／Sliderは表示しません。Enterまたは通常のフォーカス移動で確定し、
編集中に基準または他の対象ノードのstring値が外部変更された場合は未確定入力を破棄し、
基準ノードの最新値を表示します。表示更新からMayaへは書き戻さず、後のフォーカス移動でも
破棄した入力を確定しません。入力可能なままの状態通知では入力を維持します。
空文字と前後の空白をそのまま扱い、NULは書込み前に拒否します。
代表と同じ文字列を明示的に再入力した場合も、混在した他の対象ノードを揃えます。

基準の値を表示し、値の混在を示す`•`や全対象の編集可能件数は常時表示しません。
基準ノード表示であることと、操作時に全対象を確認することをtooltipで説明します。
属性行のどこを右クリックしても「表示ノードの値に揃える」と表示・ロックの操作を選べます。
「選択属性」は複数ノードを選び、選択属性の表示ノードが編集可能な場合に有効です。
全対象が同値のときに実行しても値やUndo履歴を増やしません。
各属性の基準ノードの未丸め実値を、同じ属性の他の編集可能な対象へ適用します。
未編集の行ではメニューを開くだけで値を変更しません。編集中の値はフォーカス移動として
確定します。複数属性を選んだ場合の対象は次節を参照してください。
値編集・表示とロックの画面余白からは「Step設定」を選べます。値・Step欄、Slider、
bool、enum、stringの入力欄も属性行のメニューを開きます。入力欄の文字選択と
キーボードによるコピー・貼り付けは維持します。
すべての対象が同値の入力はUndo履歴を増やしません。

たとえばAが1、Bが2でA→Bの順に選択した場合、Bの2を表示してAの1を維持します。
表示中の2へ揃えるだけなら、属性行のメニューから
「表示ノードの値に揃える > 選択属性」を実行します。
表示精度によって丸められた文字列ではなく、基準ノードの実値を適用します。

## 属性の複数選択と一括操作

Mayaのノード選択とは別に、一覧内で複数の属性行を選択できます。
選択した属性名だけを強調表示します。属性を選ぶだけでは値・状態・Undoを変更しません。
複数ノードも選択している場合は、選択した各属性について、その行の対応ノードへ操作します。

- 属性名のクリックで1行を選び、Ctrlクリックで追加・解除、Shiftクリックで連続範囲を選びます。
  Ctrl+Shiftでは範囲を現在の選択へ追加します。
- 属性名からのドラッグ、または数値欄からの縦ドラッグでも範囲を選べます。
  数値欄内の横ドラッグは文字選択として扱います。初回クリックの全選択後も、
  再クリックと横ドラッグで通常の文字編集へ移れます。
- 値編集モードで選択済みの属性を右クリックした場合は複数選択を維持します。
  未選択の属性を右クリックした場合は、その属性だけを選んでメニューを開きます。
  表示・ロックモードでは行の右クリックでメニューを開かず、属性選択も変えません。
- 同じノード群の表示更新やUndo／Redoでは、正式属性pathと型区分が一致する残存行の選択を保ちます。
  モード・フィルターを切り替えた場合も、表示に残る行だけを引き継ぎます。
  対象ノードまたは基準になる選択順が変わった場合は属性選択を解除します。
  属性選択はWindow内だけで保持し、scene・設定ファイルへ保存しません。

### 数値の直接入力

float値欄、Step欄、Slider付き値欄は、マウスで初回フォーカスした左クリックで
表示中の入力文字全体を選択します。そのまま数値を入力すると既存値を置換します。
フォーカス中の再クリックはカーソル移動、横ドラッグは任意範囲の文字選択として扱い、
上下ボタンとホイールの動作は維持します。右クリックは属性行のメニューを開きます。

複数の属性を選び、選択中の数値欄へ文字を入力するか、キーボードで数値を貼り付けると、
一括入力用の文字欄を開きます。入力は編集可能な数値欄から開始します。
一括入力欄の右クリックも入力元の属性行メニューを開き、未確定入力は
通常のフォーカス移動と同様に確定します。
一覧にフォーカスがあり、操作中の行が編集可能な数値属性の場合も入力できます。
Enter・フォーカス移動・一覧のスクロールで確定し、Escapeで取り消します。
同じ表示数値を入力し直した場合も明示的な入力として扱い、各対象へその値を適用します。
文字入力を伴わないEnter・フォーカス移動では値を揃えません。

入力開始時の選択属性を操作対象として保持します。未確定のまま選択ノード・scene・属性構成が変わった
場合や、表示更新、Windowの非表示・終了・reloadでは入力を取り消します。
それらより先にフォーカス移動が起きた場合は、移動時点で切替前の対象へ確定します。
モード・フィルターComboBoxへの移動は通常のフォーカス移動として、切替前の対象へ確定します。

数値は各行の現在の表示単位で解釈します。例えば距離・角度・単位なしの属性へ`5`を入力すると、
それぞれ現在の距離単位の5、現在の角度単位の5、単位なしの5として変換します。
基準が編集不可の行とbool・enum・string行は数値入力の対象から除外し、画面に理由を表示します。
各行の基準以外のノードに対する除外条件は、従来の型・範囲・編集可否の規則を維持します。

すべての編集対象の型・値・hard limitを先に検証し、どれかが範囲外なら操作全体を拒否します。
対象ごとのclampは行いません。成功した一括入力は全属性・全ノードを含めて1回のUndoとなり、
途中の書込み失敗は操作前の値へ復旧します。復旧も失敗した場合は両方の理由を報告します。
全対象がすでに入力値と一致していればUndo履歴を増やしません。

値欄の上下操作では、操作した行のStepから表示単位の増減量を求め、選択した各数値属性の
現在値へ同じ増減量を加えます。各行・各ノードの値の差は維持します。どれかがhard limitを
超える場合は全体を変更しません。

Step欄の直接入力と上下操作では、選択中でStep欄を持つ属性へ同じ表示stepを反映します。
距離・角度・通常数値が混在していても、各行の現在の表示単位で同じ数値を使用します。
各行のmultiplicative／additive方式は変更しません。Slider・bool・enum・stringなどStep欄のない行は
対象外として理由を表示し、未選択行のStep欄を操作した場合はその行だけを変更します。
設定をONにすると、Step欄はフォーカスがなくてもマウスオーバー中のホイールを受け付けます。
この位置では一覧をスクロールせず、Stepを変更します。値欄も同じ操作が可能です。

### Step設定の保存とリセット

整数のStepは1～2147483647です。任意の正整数を手入力でき、上下は10倍と整数除算です。
`1→10→100`、下へは`150→15→1`となり、1未満には進みません。
上限を超える増加は無効です。Step変更自体は属性値を変更しません。
floatと整数の混在選択では整数相当のStepだけを共有し、小数や整数上限超過は全体を拒否して
操作元も以前のStepへ戻します。両側hard limit付き整数行にはStep欄を表示しません。
保存済みStepはSlider表示中も保持し、Step欄がある行へ戻ると復元します。
選択Stepの共有・リセットはStep欄がある行だけが対象です。全属性リセットはSlider表示中の保存値も削除します。

整数の保存先は同じpreferences内の`integer_attribute_steps`で、識別子は属性型と正式pathの
組（例`long:count`）です。初期値は1で、同名pathでもbyte・short・longを区別します。
既存の`attribute_steps`はfloat用として維持し、両Profileをclose・再表示・reload・再起動後へ復元します。
以下の選択属性／全属性リセットは、整数の保存値も対象に含めます。

float属性のStepは`bd_channel_box/preferences/main`の`attribute_steps`へ保存し、Windowの
close・再表示、tools/utilのreload、Maya再起動後へ復元します。`reset_layout()`は
配置だけを初期化し、Step設定を維持します。sceneとMaya Undo履歴には書き込みません。

保存の識別子は正式な相対属性pathと`number`／`distance`／`angle`の組です。
node名、node型、namespace、scene、現在のcm／m・deg／radなどの単位名は含めません。
表示単位を変更しても保存した数値を換算せず、例えば0.1は新しい表示単位でも0.1として使います。
radiusは0.1、angleは15、その他は1を初期値とし、初期値と同じ設定は保存しません。
Step欄自身のmultiplicative／additive方式と増減幅は保存せず、行構築時の設定を使用します。

値編集行、または値編集・表示とロックの画面余白にある「Step設定」は、次の順で表示します。

1. `初期値に戻す: 選択属性`
2. `初期値に戻す: 全ての属性`

全属性は現在表示していない属性を含む保存済みStepを全て削除し、表示行を各行の初期値へ戻します。
選択属性は現在選択中でStep欄を持ち、保存値がある行だけを戻します。未選択行を右クリックした場合は、
従来の右クリック選択規則に従ってその行を選択してから判定します。画面余白では選択を変更しません。
対象となる保存値がない操作は無効になり、成功通知と確認dialogは表示しません。

### ホイール編集の設定

画面上部の「設定」メニューには、チェック可能な「未フォーカス時のホイール編集」があります。
初期値はOFFです。ONでは数値の値欄・Step欄・enum欄にマウスを重ねるだけでホイール編集できます。
OFFでは各欄をクリック・Tabなどでフォーカスを得た場合だけ値を変更し、未フォーカス時の
ホイールを属性一覧のスクロールへ渡します。通常の`[値][Step]`行、Slider付き行の値欄、enum欄は、
ホイール入力だけで自動的にフォーカスを取得しません。ON時の従来動作は維持します。
Slider本体とboolはこの設定の対象外です。Slider本体はフォーカスのないホイールを常に一覧へ渡します。

変更は表示中の全値入力行へ即時反映し、選択・モード・フィルター変更による行の再構築後も
維持します。設定は`bd_channel_box/preferences/main`へ保存し、Windowの再表示とMaya再起動後に
復元します。保存済みの選択は初期値より優先します。sceneとUndo履歴には書き込まず、
`reset_layout()`でも削除しません。

値欄のフォーカス制御はutilの共通部品で扱います。反映にはtoolsとutilを更新し、
`bd_tools.reload_package(reload_util=True)`で再読み込みしてください。

Sliderは選択した数値属性を操作位置と同じ表示値へ揃え、1回のドラッグを1回のUndoへまとめます。
boolは選択したbool属性を操作後のON／OFFへ揃えます。enumは操作元と整数値・項目名の定義が
一致する選択enum属性だけを同じ項目へ揃えます。異なる型とenum定義が異なる行は対象外として
理由を表示します。未選択行の部品を操作した場合は、その行だけを対象にします。
string欄の確定入力は選択中のstring行すべてへ同じ文字列を適用し、異なる型の行は
対象外として理由を表示します。各行の編集可能なノードを一回のUndoで変更します。

「フリーズ」は表示ノードがtransform系の場合だけ表示します。

値編集モードの属性行メニューは「ロック > ロック／解除」と
「表示 > Keyable／ChannelBox／Hide」を提供します。選択した全属性を1回のUndoで変更し、
値の入力可否とは別に、表示・ロックそれぞれの操作可否で対象を判定します。
ロック解除でcompound祖先を自動解除しません。enumの項目定義が違うノードも、
同じ正式属性path・型区分であれば状態操作の対象になります。
フィルターによる行の除去は状態操作を終えてから反映します。

値編集モードの「表示ノードの値に揃える > 選択属性」は、選択した各属性を
**画面上部に表示されたノードの同じ属性の値**へ揃えます。
今後ノードの決め方を変える場合も、画面に表示するノードとこの操作の値の取得元を一致させます。
例えば基準のTranslate Xが1、Translate Yが2なら、各対応ノードのXを1、Yを2へ揃えます。
数値・bool・有効なenum・stringを混ぜて選べます。編集不可の行や未定義enum値は除外し、理由を表示します。
この操作も全対象を事前検証し、書込み失敗時は復旧し、成功時は1回のUndoへまとめます。

同じメニューの「全て」「Keyable + ChannelBox」「Keyable」「ChannelBox」「Hide」は、
画面上部に表示されたノードの属性状態で対象pathを決め、同じpathを他の選択ノードへ適用します。
「全て」にはHideも含みます。表示状態の分類は属性値のペーストと共通です。
行選択・検索・Attribute Filterには依存せず、非表示の行も対象に含めます。
対応するscalar属性を扱い、値の型・enum定義・編集可否・Undoは「選択属性」と同じ規則です。
OSクリップボードは使用しません。対象がないか全対象が同値ならUndo履歴を増やしません。
属性行メニューでは、アニメーションレイヤ操作の次に区切りを挟んでこのメニューを置き、
続けて「コピー」「ペースト」、移動行では「移動をセット（子を維持）」、
回転行では「回転をセット（子を維持）」「回転をセット（姿勢を維持）」
「回転を集約」、その後に「小数点の四捨五入」と対応するXYZの丸めを配置します。

値編集モードの属性行メニューでは、「キーフレーム」と「ブレイクダウンフレーム」を
隣接して配置します。
どちらも「選択属性」「全 Keyable」の順に2階層で操作できます。
「全 Keyable」は画面の行選択・検索・Attribute Filterに依存せず、選択中の各ノード自身の
Keyable属性へ現在時刻のキーを設定します。「選択属性」は表示中の選択行と同じ正式path・型の
属性を全選択ノードへ対応付けます。未選択行の右クリックはその行だけを選択します。
非Keyableでも明示指定でキーを打てる属性は対象に含めます。キーを打てない型、ロック属性、
通常の入力接続などは状態を変えずに除外し、理由は画面へ表示しません。
「キーフレーム」は通常キー、「ブレイクダウンフレーム」はBreakdownキーを設定します。
現在時刻にキーがある場合は、選んだ種別へ切り替えます。両種別とも同じ対象選別を使い、
Mayaの現在のAnimation Layerを尊重し、通常接続へpairBlendを暗黙に挿入しません。
一度のメニュー操作は1回のUndoで戻せます。状態編集モードにはこのメニューを表示しません。

「ブレイクダウンフレーム」の次には「ミュート」「ミュート解除」を配置します。
両メニューとも「選択属性」「全アニメーション属性」の順に表示します。
「選択属性」は表示中の選択行と同じ正式path・型の属性を全選択ノードで対象にし、
Attribute Filterを「全て」にして選んだHide属性も含めます。
「全アニメーション属性」は各選択ノード自身のKeyableまたはChannelBox表示属性を対象にし、
このツールの検索・Attribute Filter・行選択には依存しません。Hide属性は含めません。
いずれも入力接続のない属性や変更できない属性は静かに除外します。
ミュートはMayaのチャンネル単位の操作で、時間カーブだけでなくExpressionなどの入力接続も
対象になり得ます。Animation LayerやTime Editor全体のミュート状態は切り替えません。
解除には`mute -disable`を使い、ミュート状態に付けたキーを削除し得る`-force`は使いません。
一度のメニュー操作は1回のUndoで戻せ、成功通知は表示しません。

「ミュート解除」の次に区切りを置き、「アニメーションカーブ：コピー」
「アニメーションカーブ：ペースト」「アニメーションカーブ：カット」
「アニメーションカーブ：削除」を並べます。
続けて区切りの下へ「アニメーションレイヤ：追加／除去」、さらに区切りの下へ
「表示ノードの値に揃える」、属性値の「コピー」「ペースト」を置きます。
移動属性の行では「移動をセット（子を維持）」、回転属性の行では
「回転をセット（子を維持）」「回転をセット（姿勢を維持）」
「回転を集約」を続け、
その後にfloat系の「小数点の四捨五入」と対応する移動・回転属性のXYZの丸めを置きます。
アニメーションカーブの四項目は状態編集モードには追加しません。
カーブのコピー・カット・削除には
「選択属性」「全アニメーション属性」の順、貼り付けには
「選択属性」「コピー元と同じ属性」の順で子項目を表示します。

カーブの「選択属性」は選択行と対応する全選択ノードを扱い、明示して選んだHide属性も
含めます。「全アニメーション属性」は各選択ノードのKeyable／ChannelBox表示属性から
実際にキーを持つカーブだけをコピーします。画面の検索・Attribute Filter・行選択には
依存せず、Hide属性は含めません。Expressionなどカーブではない入力はコピーしません。
コピーは全時間のキーを扱い、属性値用のOS clipboardと独立したMayaのキー用clipboardを
更新します。このツールの貼り付けにはコピー時の曲線と属性pathを画面内にも保持するため、
ほかのMaya操作でキー用clipboardが変わっても属性の誤対応を起こしません。
画面を閉じる・reloadすると、このツールで保持したコピー情報は失われます。
コピー自体はsceneとUndo履歴を変更しません。

「コピー元と同じ属性」はコピーした正式pathと一致する属性へ型を問わず貼り付けます。
「選択属性」はコピー元が一曲線なら型を問わず選択属性へ展開し、複数曲線なら選択属性のうち
同じ正式pathのものだけを貼り付けます。カーブの順番だけで別属性へ割り当てません。
同名属性の型が選択ノード間で異なる場合も、曲線の貼り付け先は各ノードで個別に判定します。
enumの項目名の対応が異なる属性も対象にできますが、属性として評価される値や意味は
貼り付け先の定義に従います。
コピー元が一ノードなら全選択ノードへ展開し、複数ノードなら貼り付け先も同数を選択して
選択順で一対一に対応させます。対象のない属性やキー設定できない属性は除外します。
ツール独自の単位変換や丸めは加えず、Mayaの`pasteKey`へ任せます。boolやenumに貼っても
カーブの小数キー値は保持されますが、属性の評価値は真偽値や整数になります。
doubleAngleは表示数値を保つため、Mayaが内部のキー値をラジアンへ変換します。
貼り付けはMaya標準のChannel Boxと同じく、現在時刻を開始点に`insert`で挿入し、
既存カーブの値へ`connect`します。後続キーの時刻や、接続先の既存カーブがある場合の
貼り付け値は変化し得ます。一度の貼り付けは1回のUndoで戻せ、成功通知は表示しません。
Animation Layerの合成結果やDriven Keyのdriver接続は複製しません。

カーブの「カット」は、削除と同じ対象範囲から、コピーできる曲線だけを全時間で
コピーして削除します。「選択属性」は型が異なっても同じ正式pathを持つ全選択ノードを
対象にし、明示したHide属性も含みます。「全アニメーション属性」は各ノードの
Keyable／ChannelBox表示属性を画面の検索・フィルター・行選択と独立して対象にします。
共有曲線は削除と同様に除外し、コピーと削除の対象を一致させます。
カットした曲線はMaya標準のキー用clipboardとこの画面の貼り付け情報へ保持します。
通常の曲線は評価値が固定値として残り、削除は1回のUndoで戻せます。
Animation LayerはMaya標準の作用範囲に従い、全レイヤーを一括ではカットしません。
対象がない場合はclipboard、scene、Undo履歴を変更せず、成功通知も表示しません。

カーブの「削除 > 選択属性」は、選択行と同じ正式pathを持つ全選択ノードの属性を
型にかかわらず対象にします。明示して選んだHide属性も含みます。
「削除 > 全アニメーション属性」は各選択ノードのKeyable／ChannelBox表示属性を
画面の検索・Attribute Filter・行選択と独立して対象にし、Hide属性は含めません。
いずれも実際にキーのある属性だけを扱い、Expressionやconstraintなどカーブ以外の
直接入力接続は削除しません。複数の出力接続先を持つ共有曲線は、他属性への波及を
防ぐため除外します。

削除はMaya標準のChannel Boxと同じ`cutKey -clear`を使い、対象曲線の全時間のキーを
削除します。通常の曲線ではanimCurveノードも消え、削除時刻の評価値が固定値として
残ります。ミュート中の曲線やDriven Keyも対象になり、ミュートノードも消え得ます。
Animation Layerに複数の曲線がある場合、一度の操作で全レイヤーの曲線を削除する
ものではなく、Maya標準の作用範囲に従います。Mayaのキー用clipboardとこの画面の
コピー情報は変更せず、一度の削除は1回のUndoで戻せます。対象がない場合は
sceneとUndo履歴を変更せず、成功通知も表示しません。

アニメーションレイヤの「追加」「除去」は値編集モードの属性行メニューに表示し、
アニメーションレイヤエディタで選択中の実レイヤすべてを対象にします。
レイヤが未選択、またはBaseAnimationだけが選択されている場合は無効です。
両メニューとも「選択属性」「全 Keyable」の順に表示します。
「選択属性」は表示中の選択行と同じ正式path・型を持つ全選択ノードを対象にし、
明示選択した非Keyableの数値属性も含めます。文字列などMayaが扱えない属性は除外します。
「全 Keyable」は選択中の各ノード自身のKeyable属性を扱い、画面の検索・
Attribute Filter・行選択には依存しません。非Keyable属性は、選択操作で登録済みでも
「全 Keyable」による除去対象には含まれません。登録済みの追加と未登録の除去は変更せず、
一度の操作は1回のUndoで戻せます。除去では所属だけでなく対象レイヤ上のキーも失われ、
他レイヤへキーを移しません。成功・対象外の通知は表示しません。

### 属性値のOSクリップボードCopy/Paste

メニューバーの「編集」と、値編集モードの属性行メニューには、同じ構成の操作があります。

- `コピー > 選択属性`: 現在選択している属性だけをコピーします。
- `コピー > 全属性`: 現在の基準nodeで対応している全属性をコピーします。
- `ペースト > 選択属性`: コピー値が複数なら、現在選択した属性と同じ正式pathだけを
  貼り付けます。コピー値が一つなら、その値を現在選択した互換属性すべてへ貼り付けます。
- `ペースト > コピー元と同じ属性：全て`: コピー情報に含まれる全正式pathへ貼り付けます。
- `ペースト > コピー元と同じ属性：Keyable + ChannelBox`: 貼り付け時の基準nodeで
  KeyableまたはChannelBoxのコピー項目へ絞ります。
- `ペースト > コピー元と同じ属性：Keyable／ChannelBox／Hide`: 貼り付け時の基準nodeで
  各表示状態のコピー項目へ絞ります。

Copyは現在の基準ノードからbool・byte・short・long・number・distance・angle・enum・string属性を取得します。
表示とコピー元を一致させるため、複数選択時も末尾の基準ノードから取得します。
「全属性」は行選択や現在のAttribute Filterに依存せず、「選択属性」は表示中の行選択だけを
対象にします。値は表示文字列へ丸めず、distanceはcm、angleはdegree、通常数値は単位なしの
公開単位で保存します。enumの実整数と項目定義も型付きで保存し、stringは実文字列を保持します。
CopyはsceneとUndo履歴を変更しません。

「コピー元と同じ属性：全て」は、OSクリップボード内の全属性を現在選択中の1個または
複数nodeの同じ正式pathへ適用します。ほかの四項目は、現在の末尾の基準nodeで
Paste時点の表示状態から対象pathを一度決め、その同じpathを全選択nodeへ適用します。
基準以外のnodeごとの表示状態では再判定しないため、一操作の一部nodeだけが条件外にはなりません。

`keyable + channelbox`はKeyableまたはChannelBox、`keyable`はKeyable、`channelbox`は
非KeyableかつChannelBox、`hide`はKeyableでもChannelBoxでもない属性です。画面上部の
Attribute Filterとは独立して明示的に選び、選択した条件は保存しません。条件外のコピー項目数は
内部のPaste結果へ保持し、画面には表示しません。対象pathが0件ならsceneとUndo履歴を変更しません。

複数項目をコピーした後の「選択属性」は、OSクリップボード内の値から現在選択した属性と
同じ正式pathだけを取り出します。`translate.translateX`のような正式な相対pathと
型・単位区分が一致する属性だけを対象とし、行順やクリック順による対応付けは行いません。
選択pathがクリップボードにない場合は、コピー値なしとして内部結果の対象外にします。

一項目だけをコピーした後の「選択属性」は、コピーした一値を現在選択している属性pathと
全選択nodeへ展開します。Paste時にコピー元pathを右クリックする必要はありません。
byte・short・long・number・distance・angle・bool・stringは同じ型区分同士に限定し、enumは整数値と項目名の定義が
一致する属性だけを対象にします。コピー元pathと貼り付け先pathの一致は要求しません。

enumは整数値と項目名の対応が一致する場合だけ対象にし、表示順だけの違いは許容します。
属性なし、型・単位違い、enum定義違い、lock・未対応の入力接続などの編集不可属性は対象外として
内部結果へ理由を保持します。残った全対象の型・hard limitを先に検証し、一回のUndoで変更します。
対応する接続属性には通常の値入力と同じ規則を使います。通常時間カーブとAnimation Layerは
MayaのAuto Keyに従い、Driven Keyは一時的な値だけを変更します。
途中失敗は操作前の値・キーへ復旧し、全対象が同値ならキーもUndo項目も作りません。

Pasteの成功・部分適用・対象0件では画面へ操作通知を表示せず、以前の通知も消去します。
未対応versionや壊れたJSONなど、Paste処理を開始できない場合だけ簡潔なエラーを表示します。

custom MIMEとmarker付きtextへversion付きJSONを保存するため、別のMaya processからも
貼り付けられます。未対応version、壊れたJSON、過大data、未知の型は値を書き込む前に拒否します。
整数属性を含む書込みはschema version 3を使用し、version 1・2の従来データも読み込めます。
Copy元は一つの基準nodeに限定し、全対応属性または選択属性をコピーします。
複数source nodeを行順・選択順で対応させるPasteは提供しません。

### float属性の小数点の四捨五入

値編集モードのfloat系属性行では、「小数点の四捨五入」を表示します。
移動・回転XYZ行では専用の「セット」と回転の集約の下に配置します。
number・distance・angleと対応するcompound子が
対象です。bool・enum・string・整数・timeには表示しません。
「選択属性」「全て」「Keyable + ChannelBox」「Keyable」「ChannelBox」「Hide」の
各子メニューに、`0（整数）`、`0.1`、`0.12`、…の桁数候補を置きます。
候補は0桁から右クリックした行に**現在表示されている小数桁数**までです。
Mayaの`channelsPrecision`を変更しても既存行の候補はそのままで、表示更新・行の再生成後に
新しい設定の桁数を反映します。メニューを開く時だけ候補を生成します。

「選択属性」は表示中に選んだfloat系の行だけを対象にします。ほかの型の選択行は除外します。
ほかの五つの範囲は画面上部の基準ノードの属性表示状態で正式pathを選び、
現在の行選択・検索・Attribute Filterで見えない属性も含めます。
「全て」にはHideも含み、表示状態の分類は属性値のペーストと共通です。
同じ正式pathと単位種別の属性が全選択ノードにあれば、それぞれの**未丸め実値を個別に**
四捨五入します。基準ノードの値へ揃える操作ではありません。
距離・角度は各属性の現在のMaya表示単位で丸めます。十進のちょうど中間は正負とも
ゼロから遠い側に進め、0桁は整数に丸めます。
ロックや未対応接続など編集できない属性は除外し、hard limitは書込み前に検証します。
通常時間カーブ・Animation Layer・Driven Keyの値編集は既存の入力規則に従い、
一操作を1回のUndoで戻せます。値が変わらない場合はUndoを追加しません。

### translateXYZ／回転XYZの小数点の四捨五入

値編集モードの`translateX/Y/Z`行では、汎用の「小数点の四捨五入」の次に
「translateXYZ 小数点の四捨五入（子の座標を保持）」を表示します。
`rotateX/Y/Z`、`rotateAxisX/Y/Z`、`jointOrientX/Y/Z`行では、同じ位置に
対象の属性群名を先頭にした「［属性群］XYZ 小数点の四捨五入
（子の姿勢を保持）」と「［属性群］XYZ 小数点の四捨五入
（子の座標/姿勢を保持）」を表示します。例えば`rotateX`の行では
`rotateXYZ`から始まる二項目だけを置きます。
回転系の二項目には「子 joint は、rotate で調整」と
「子 joint は、jointOrient で調整」の子メニューをこの順に置きます。
各末端の候補は`0（整数）`、`0.1`、`0.12`、…で、0桁から右クリックした行に
現在表示されている小数桁数までです。Mayaの`channelsPrecision`を変更した場合は
表示更新・行の再生成後に新しい上限を反映します。

右クリックした軸は対象となる属性群を決めます。一度の操作で選択中の
Transform／JointそれぞれのXYZをまとめて丸め、複数行を選んでも同じノードは
一度だけ扱います。`jointOrient`はJointだけを対象とし、選択中のTransformは
対象外として理由を表示します。距離・角度は現在のMaya表示単位で丸めます。
丸め方は汎用メニューと同じ十進の四捨五入です。
移動の丸めは子のworld座標を保持し、回転系は選んだ項目に応じて子のworld姿勢、
またはworld座標と姿勢の両方を保持します。子Jointの姿勢補償先は子メニューで指定します。

処理には`bdUtilCommands`の`bdRoundTranslate`、`bdRoundRotate`、
`bdRoundRotateAxis`、`bdRoundJointOrient`を使用します。対象ノードの変更は
一度のメニュー操作で1回のUndoとして戻せます。ロック・入力接続などで
コマンドが変更できない場合はエラーを表示し、変更なしならUndoを追加しません。

### 子を維持する値設定・姿勢を維持する回転設定

値編集モードの`translateX/Y/Z`行には「移動をセット（子を維持）」を表示します。
`rotateX/Y/Z`、`rotateAxisX/Y/Z`、`jointOrientX/Y/Z`行には
「回転をセット（子を維持）」と「回転をセット（姿勢を維持）」を表示します。
右クリックした軸は起動の入口で、属性群を新ツールの設定先へ渡します。

移動と回転の子維持メニューは、独立ツール
[bdChildCompensatedSet](bd_child_compensated_set.md)の共通2タブWindowを開きます。
姿勢維持メニューは独立ツール
[bdRotationPreservingPose](bd_rotation_preserving_pose.md)を開きます。
どちらもbdChannelBoxを閉じた状態から単独起動でき、現在選択の末尾にある
TransformまたはJointの1ノードだけを操作します。Window固有の値入力、
Step、設定保存、Mayaドックの仕様は各ツールの文書を参照してください。

### 回転の集約

値編集モードで`rotateX/Y/Z`、`rotateAxisX/Y/Z`、`jointOrientX/Y/Z`の行を
右クリックした場合だけ、「回転をセット（姿勢を維持）」の次に
「回転を集約」を表示し、続けて丸めの項目を置きます。
子項目は「rotate に集約」「rotateAxis に集約」、基準ノードがJointの場合は
「jointOrient に集約」も加えます。表示中の行や選択属性の種類は入口を決めるだけで、
操作対象の軸を限定しません。

選択中の各Transform／Jointを重複なく一度ずつ扱い、そのノードの現在の回転全体を
指定した属性群へ集約します。Transformでは`rotateAxis`と`rotate`、Jointでは
さらに`jointOrient`を合成し、集約先以外のXYZ値をゼロにします。
現在のlocal matrixと`rotateOrder`は維持します。Joint専用の集約先を選んだときは
Transformを対象外として画面に通知します。

回転群の親または子にlock・入力接続があるノードは、既存NodeOperatorの規則に従って
対象外とし、理由を画面に示します。キーフレームやAnimation Layerの接続を持つ
回転属性も対象外です。複数ノードの集約は1回のUndoで戻せます。
既に回転が集約先だけにあるノードは変更せず、全対象が同じ状態ならUndoを追加しません。
集約値の計算と入力可能性の検証はutilのNodeOperatorと共有し、Maya表示角度単位で
値を確定します。集約中に書込みが失敗した場合は、成功済みの変更も復旧します。

### transformのフリーズ

値編集行の属性値「ペースト」、移動・回転行の「子を維持」した値設定、
回転行の「回転をセット（姿勢を維持）」と
「回転を集約」、float系の「小数点の四捨五入」、
対応する移動・回転行のXYZの丸めの下に区切りを置き、
「フリーズ > 移動／回転／
スケール／全て」を表示します。
フリーズは末尾の基準ノードがtransform系の場合だけ表示し、非transformのときは
フリーズと直前の区切りを隠します。状態編集モードには表示しません。

フリーズは右クリックした属性や選択行ではなく、選択中のtransform系ノードを対象にします。
混合選択の非transformノードは対象外です。Maya標準と同じ`makeIdentity -apply true`で
指定成分をフリーズし、形状がある場合はそのワールド位置を保つよう補正します。
「移動」はjointに作用しないため、jointのみの選択では無効にします。
「全て」でもjointの移動値は残り、回転のフリーズはjointOrientを変更し得ます。
キー・入力接続・ロックがある成分は勝手に解除せず、Mayaが拒否したエラーを表示します。
一度のフリーズは1回のUndoで戻せ、成功通知は表示しません。

値編集・表示とロックの余白メニューは「Step設定」を提供します。値編集行の右クリックでは、入力部品の種類に
かかわらずその行のメニューを開きます。文字列そのものを外部へコピーする場合は、文字列欄で
対象の文字を選択してCtrl+Cを使います。属性値のCopyは専用形式を保存します。
Maya標準Channel Boxの選択やメニューには連動しません。
接続解除とGraph Editor連携はこの段階の対象外です。

## 範囲、単位、編集不可

両側のhard min/maxが有限で最小値より最大値が大きいfloatには
`FloatSliderSpinBox`、それ以外には`FloatValueStepSpinBox`を使用します。
通常float行は`[Value][Step]`、Slider行は`[Value][Slider]`の順に配置します。
整数の両側hard limitが`Min < Max`を満たす場合は`IntSliderSpinBox`、
それ以外は`IntValueStepSpinBox`を使用し、同じ順序と幅で配置します。
範囲はutilの`MayaIntPlugsBinding.hard_limits`から取得します。
型固有の上下限、片側制限、soft limit、同値制限だけでは整数Sliderを表示しません。
byteは下限・上限の組が型既定の0～255に一致する場合だけ、両側を未指定として扱います。
同じ全範囲を明示指定した場合も同様です。0～31や10～255などの狭い範囲は両端を保持します。
Maya上で実際に片側のhard limitが未指定なら、その側は未指定のままです。
byteの生成時のmin/max指定はMayaが上書きするため、独自の制限は定義後の
`cmds.addAttr(path, edit=True, minValue=..., maxValue=...)`で設定します。
属性定義を変更した後に画面を更新するとSlider／Stepを再選択します。

float系のSlider付き行は、utilの`FloatSliderSpinBox`の型別既定stepを使います。
角度（doubleAngle）は値欄の上下・ホイールを1刻み、通常数値・距離は0.1刻みにします。
現在の表示単位を使うため、角度の1は度表示では1度、radian表示では1radです。
Sliderの分割数・ドラッグの分解能と、小数の表示・手入力精度はこのstepから独立しています。
Sliderがない角度行のStep既定15と、保存済みStepの扱いは維持します。

transform標準属性での代表例は`objectColor`（short、0～7）と
`overrideColor`（byte、0～31）です。Attribute Filterを「全て」にして属性名で検索すると
確認できます。`layerOverrideColor`も0～31ですが、Mayaの旧式属性です。
初回実装ではbyteの下限0を個別に除外していたため`overrideColor`がStep表示に
なっていましたが、この判定を修正しました。値入力の0～31という制限は従来から維持しています。

整数Sliderの範囲は基準ノードの設定を使い、書込みは編集可能な全対象の制限を検証します。
他ノードの狭い範囲へ暗黙に補正せず、不正な更新は全対象へ適用しません。
既に成功したドラッグの更新は最後の確定値として維持し、Undo一回で操作前へ戻せます。
選択中の整数・float行には同じ表示整数を適用し、整数演算のまま32-bit両端を扱います。
値欄とSlider表示範囲は独立し、Sliderの範囲外の確定値も値欄に保持します。
値欄の上下操作の刻み幅は1、Sliderは最大1000分割です。
Min／Maxを編集する欄はbdChannelBoxへ追加せず、汎用Viewの範囲編集はutilのサンプルで扱います。

値欄は156 px、Step／Sliderは共通の60 px、欄間は6 pxに固定します。
値欄は`1234.123456789123456`の20文字を見渡せる幅を目安にしています。
通常float行はutilの`value_width`・`step_width`を使い、Sliderにも同じ幅を指定します。
数値入力グループ全体を222 pxで右寄せし、画面を広げた分は属性名側へ配分します。
boolも同じ幅の入力列を確保し、その中でチェックを左詰めにします。
Sliderの有無によらず、入力欄の左端・右端とStep／Sliderの開始位置が揃います。
片側のhard limitも数値入力では尊重します。soft limitは初版では使用しません。
Mayaの表示単位へ追従し、小数桁数は行の生成時にChannel Box設定から取得します。
値欄の拡張は表示領域だけの変更で、小数桁数の設定やMayaの数値精度は変更しません。
値欄・step欄の単位文字（cm / degなど）は、Slider付きの値欄も含めて非表示です。
文字を省略しても、現在の表示単位での数値表示・入力と単位変更時の換算は継続します。

Slider以外の行には、値欄の右へ `step` 欄を表示します。
フィールド内の「step」表記は省略し、4桁程度が収まるコンパクトな幅にします。

| 属性 | step変更方式 | 初期値 | step欄の上下操作 |
| --- | --- | --- | --- |
| 距離（doubleLinear） | multiplicative | 1 | 0.1 ↔ 1 ↔ 10 |
| 角度（doubleAngle） | additive | 15 | 15 ↔ 30 ↔ 45 |
| その他のfloat / double | multiplicative | 1 | 0.1 ↔ 1 ↔ 10 |
| 正式属性名がradius | multiplicative | 0.1 | 0.01 ↔ 0.1 ↔ 1 |

radiusは型の設定より優先します。Slider行にも同じ値欄幅を適用します。
stepの変更だけでは属性値・Undo履歴を変更せず、次の値欄の上下操作から適用します。
stepは現在の表示単位で扱い、単位変更時も数値を維持します（例: step 1 cm → 1 m）。
step欄への直接入力も可能です。ロック等で値が編集不可でも、step設定だけは変更できます。

変更したstepは正式属性pathと型区分（数値／距離／角度）ごとに保持します。
別ノードの同属性、選択解除・再選択、更新、Undo / Redo、scene切替でも維持し、
複数選択への入力時は対象となった各属性の設定を同時に更新します。その後は各行を
個別に変更できます。初期値と異なるstepは`bd_channel_box/preferences/main`へ保存し、
Windowの終了・reload・Maya再起動後も復元します。sceneとUndo履歴には保存しません。
モードやフィルターの切替でもstep設定を維持します。

表示範囲は基準属性を使い、他対象の制限は書込み前に検証します。
入力がどれかの編集可能な対象の範囲外なら、その入力全体を拒否して理由を表示します。
対象ごとに値を黙ってclampすることはありません。
属性の表示名・範囲設定を変更した後は、ノード選択を一度解除して選び直すと
View構成を読み直せます。

自身またはcompound祖先にlockがある属性や、未対応の入力接続がある属性は編集不可です。
対応するアニメーション接続では、以下の規則で一時値またはキーを変更します。
基準が編集不可なら行全体の値入力を止めます。基準以外の編集不可属性は除外し、
残る編集可能な対応属性へ適用します。tooltipは基準の状態を示し、全対象の適用候補数と
除外理由は操作結果として通知します。

### 入力接続の表示

値編集モードでは、属性名と入力欄の間に幅6pxの表示領域を置きます。
接続色は上下1pxずつ余白を空け、隣り合う行の色帯を分離します。
基準ノードの属性について、次の状態を示します。

| 状態 | 色 | 判定 |
| --- | --- | --- |
| 現在時刻にキーあり | `#CD2729` | 通常の時間カーブが直接接続され、現在時刻にキーがある |
| アニメーションあり・現在キーなし | `#DD727A` | 同じカーブが接続され、現在時刻にキーがない |
| Key Altered | `#FDCBC4` | 現在のplug値が通常時間カーブの現在時刻の評価値と異なる |
| Driven Key | `#5099DA` | unitless入力のアニメーションカーブが直結している |
| Expression | `#CBA5F1` | expressionノードが直結している |
| Animation Layer | `#4DB6AC` | animLayerへ接続されたanimBlendNodeが直結している |
| Animation Clip | `#FFCC80` | Time EditorのtimeEditorInterpolatorが直結している |
| Muted | `#BFA182` | 直結するmuteノードのmuteが有効 |
| pairBlend接続 | `#ACF1AC` | 自身またはcompound親へpairBlendが直結している |
| constraint接続 | `#A3CBF0` | 自身またはcompound親へconstraint系ノードが直結している |
| その他の入力接続あり | `#F1F1A5` | 直結元が上記以外の入力。演算ノード経由の入力など |
| Nonkeyable | `#949494` | 入力接続がなく、keyableが無効 |
| 入力接続なし | Mayaの通常背景色 | 入力接続がなく、keyableが有効 |
| ロック | `#5C6874` | 自身またはcompound親がロックされている |

この表は[AutodeskのChannel Box色一覧](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-Basics/files/GUID-4C954FB2-8B6A-4BBD-9695-DF432616D0D2.htm)にある13種類を網羅します。
入力接続なしの通常背景色は、Maya標準の未着色状態として追加しています。
状態色は固定RGBで、Mayaのユーザー設定による色変更とは連動しません。

キーの判定はサブフレームも含めて現在時刻に厳密に一致するキーを対象とします。
Key Alteredは現在時刻だけで比較し、別時刻を指定した照会ではキー有無を返します。
muteを解除した際はその入力元を分類し直します。Time Editor全体のミュートなどで
実接続が外れた場合はAnimation Clip色を表示しません。
接続種類はアトリビュート名でなく直結元ノードの型で判定します。ロック色を最優先し、
ロック中も元の接続状態を保持してtooltipへ示すため、解除すると接続色へ戻ります。
実効muteは下流の入力元より優先し、通常時間カーブではKey Alteredを現在キーの有無より
先に判定します。Nonkeyableは入力接続がない場合だけ表示します。
判定は`sourceWithConversion()`が返す直接の接続元とcompound祖先の接続を使用し、
任意の上流ノードを再帰探索しません。`unitConversion`を経由する場合はそのノードが
直接の接続元となり、現状は「その他の入力接続あり」として表示します。
帯は読み取り専用の補助表示です。referenceなどによる編集可否は色分けしません。
複数ノードでも基準ノードの色と状態だけを表示し、他ノードの接続・ロックは操作時に確認します。
時刻移動、キーの追加・削除、接続・ロックの変更、Undo／Redoに追従します。

状態を拡張する際は、utilの`plug_input_state.py`で分類と通知対象を定め、
toolsの`widget.py`で色・tooltipを追加します。Mayaの実接続を作るutilのMaya testと、
表示画素を調べるtoolsのMaya testを更新し、必要ならMaya本体で色と優先順位を確認します。
色帯の追加によって値の書込み可否やキー設定先を変更しない方針です。

### アニメーション属性の値編集

number・distance・angle・bool・enum属性について、通常時間カーブ、Driven Key（SDK）、
Animation Layerへの値入力を許可します。keyable／channelBoxの表示状態は変更しません。

値欄の確定入力、上下・ホイール、Slider、bool・enum、「表示ノードの値に揃える」、各Paste経路に
同じ規則を適用します。未接続の対象は通常の値設定とし、新しくアニメーションを開始しません。
通常時間カーブとAnimation Layerは、MayaのAuto KeyがOFFなら一時的な値だけを変更し、
ONならMayaの対象選択に従って既存アニメーションへキーを追加・更新します。
SDKはAuto Keyによらず一時的な値だけを変更し、Driven Keyの設定は別操作です。
整数の直接入力・上下・整列・値Pasteにも同じ規則を適用します。
値と入力範囲は整数で検証しますが、元のカーブの小数キーや接線は丸め直しません。
同値判定と入力接続表示は属性の整数評価値を基準にし、Undo・失敗復旧では元のキーを保持します。
一時値は時刻変更やドライバー変更・再評価で接続元の評価値へ戻ります。
まだ時間キーを持たないLayerなど、時間に依存しない構成では、時刻移動だけで再評価が
発生せず一時値が残る場合があります。
再表示・時刻移動・同値入力だけではキーもUndo項目も作りません。
各対象の評価値と入力値を比較するため、基準が同値でも値が異なる他の対象だけは更新します。

キー設定先と合成値の解決はMayaの標準動作へ委譲します。Animation Layerの選択、ロック、
ミュート、ウェイトによって、別レイヤへのキー設定や、入力と最終出力の不一致が起こり得ます。
対象ごとの入力方針と現在のレイヤ設定先はtooltipで確認できます。
上下操作は各対象の評価済み現在値へ同じ表示増減量を加え、値の差を維持します。
Sliderも操作中のAuto Key設定に従い、一ドラッグを一回のUndoへまとめます。
ドラッグ中に現在時刻が変わったら操作を確定終了し、古いマウス移動を次の時刻へ適用しません。
値欄の未確定数値入力も時刻変更で破棄します。同時刻の再評価だけでは入力を終了しません。

表示の正本は引き続き評価済みMaya plug値です。値の書込み後にplugを読み直し、
ViewModelへ同期します。複数行・複数ノードに通常値とキー編集が混在しても全件を事前検証し、
一回のUndoで復元します。途中失敗では新設キーを除去し、更新前のキーと通常値へ復旧します。

constraintはMaya標準では値入力できる構成でも禁止します。Animation Layerなどの上流に
constraintが含まれる対象も除外します。一般のpairBlend、Mute、Animation Clip、expression、
unitConversion経由、その他の未対応接続は入力不可のままです。
SDKとLayerの合成、複数属性で共有するカーブ、独自の時間入力や未対応の回転補間も対象外です。
接続を解除・置換したり、ロックを自動解除したりしません。
キー設定メニューもLayer内部の未対応接続を除外し、SDKのキー設定は扱いません。

一回の数値確定・上下操作・bool変更・enum項目変更・string確定は、選択した全属性・全ノードを含めて
一回のUndoで戻ります。Sliderドラッグも全対象を含めて一回のUndoへまとめます。
Undoでは混在していた各属性・各ノードの元値が戻ります。
途中の書込み失敗は同じ操作内で復旧し、復旧にも失敗した場合は両方の理由を報告します。

## 表示・ロック

属性名の右側を、`key / ch / hide`のラジオボタンと`lock`のCheckBoxへ切り替えます。
表示状態の3つだけを排他的に選択し、ロックは独立して操作できます。
ラジオボタンから左ドラッグすると、開始した列の通過行をその状態へ変更できます。
例えば`ch`列を縦になぞると、その範囲の属性をChannelBoxへ揃えられます。
選択済みのボタンからも開始でき、通常クリック・キーボード操作は維持します。
小さな手ぶれは通常クリックとして扱い、速い移動でも経路上の途中の行を対象にします。
`lock`から左ドラッグすると、基準の押下時がOFFならロック、ONなら解除へ通過行を揃えます。
基準が既に目的の状態でも他の対象へ要求し、全対象が同じ場合だけ変更しません。
同じ行を往復しても再反転せず、一部の対象が操作不可でも、その行への再要求は一操作一回です。
通常クリック・Spaceキーでの操作も維持します。
ラジオボタンから始めた操作はラジオボタンだけ、`lock`から始めた操作は`lock`だけを対象にします。
両操作とも表示範囲内の有効なボタンだけを対象とし、画面外の行は変更しません。
なぞり中のホイール移動と画面端の自動スクロールには対応しません。

なぞった変更はその場で反映し、一回のUndo／Redoにまとめます。無変更なら履歴は増えません。
フィルターによる行の除外は操作終了まで保留します。マウス解放、Escape、非表示、
フォーカス喪失、モード・選択・scene・属性構成の変更、終了・reloadで入力を止めます。
中断ではそれまでの変更を保持し、戻す場合はUndoを使います。
書込み失敗時は失敗した行を既存Bindingが復旧し、なぞり全体を終了します。
それ以前に変更した行は保持し、一回のUndoで元へ戻せます。

設定モードの操作欄は`key`・`ch`・`hide`・`lock`を6 px間隔で並べた必要幅です。
`hide`と`lock`の間に伸縮余白は置きません。狭いWindowでは属性名の省略が増えますが、
正式な名前はtooltipで確認できます。各ボタンのtooltipには省略前の意味も表示します。

| 表示状態 | keyable | channelBox |
| --- | --- | --- |
| key（Keyable） | True | False |
| ch（ChannelBox） | False | True |
| hide（Hide） | False | False |

Keyableはキー設定可能、ChannelBoxはキー設定不可でChannel Boxへ表示、
Hideはキー設定不可でChannel Boxから非表示の状態です。
既存属性のkeyableとchannelBoxが両方Trueの場合はKeyableとして表示します。
Hideは上記のplug状態だけを変更し、属性定義のhiddenや属性自体は変更・削除しません。
表示状態はロックを変更せず、ロック／解除は表示状態を変更しません。値やキーにも書き込みません。

属性定義によってkeyableとchannelBoxが両方Trueになっている特殊な属性は、
Maya標準Undoで元の組合せを復元できないため、表示状態の変更対象から除外します。
基準ノードの属性がこの状態なら、その行の表示状態の操作全体を無効にします。
基準以外だけが該当する場合は、その対象を除いて残りへ適用します。
理由はtooltipへ表示し、状態の自動修正や属性定義の変更は行いません。
この制限は表示状態にだけ適用し、ロック／解除は通常の操作可否に従って利用できます。

複数選択の対象は、値編集と同じ正式属性path・型区分の属性です。
enumの項目定義は変更しないため、定義が異なるenumも状態編集の対象になります。
表示とlockは基準ノードの状態だけを示します。全対象の混在・変更可能件数は常時計算せず、
属性名の「•」や三状態CheckBoxも表示しません。属性と操作可否は明示入力時に全対象を調べ、
操作結果に適用候補と除外理由を示します。
表示同期だけでは揃えません。選択中の行の`key / ch / hide / lock`を操作すると、
操作後の表示状態またはlockを、選択属性すべてと各選択nodeへ適用します。
選択外の行の操作部品は、現在の選択集合を変更せず、その行だけを対象にします。
ラジオボタンはクリック・Space・矢印キーで選択できます。基準と同じ状態の再選択でも、
他の対象に差分があれば変更します。全対象が同状態ならUndo履歴を増やしません。
lockは基準がOFFなら全対象をロック、ONなら全対象を解除する二状態の操作です。
属性名と入力欄のtooltipで、基準だけの表示であることと基準の操作できない理由を示します。

左ドラッグがなぞり操作の開始距離を超えた場合は、属性選択へは展開しません。
表示状態は通過した同じ列のradio、lockは通過したCheckBoxだけを開始時の
操作に揃え、既に選択されている離れた行は変更しません。単発クリックとなぞりは、
どちらも操作単位を1回のMaya標準Undoへまとめます。
同じ行への適用は一ドラッグで一回とし、基準が同じ表示状態やlockでも他の対象へ要求します。
別列は対象に含めず、フィルターによる行の再構築だけを終了時まで保留します。
選択やscene・構成の変更とWindow終了では古い操作を終了します。

ロック中や入力接続済みの属性でも、表示状態の編集や自身のロック解除を操作できます。
値編集の可否判定は流用せず、状態ごとに操作可否を判定します。
compound祖先がロックされている場合、子の操作で祖先まで自動解除しません。
自身のロックと親による制限は区別して表示します。
状態行では右クリックメニューを開かず、属性選択も変えません。
表示・ロックの操作は行内のボタンで行います。
画面余白のメニューから「Step設定」を選べます。

1回の表示状態変更、またはロック変更を、それぞれ1回のMaya標準Undoへまとめます。
Undoでは対象ごとに異なっていた状態と元のkeyable／channelBoxの組合せを復元します。
同じ状態への入力はUndo履歴を増やしません。外部変更とUndo／Redoにも追従します。

## 更新と終了

選択、属性追加・削除、keyable/channelBox切替、改名、Undo/Redo、scene切替で
構成を再取得します。「全て」では表示フラグだけの変更による全行再構築は不要です。
通常の値変更では全行を作り直さず、Bindingで表示を同期します。
utilの複数属性Bindingはdirtyになったplugと祖先を照合し、関係する行だけを読み直します。
「全て」で多数の行を表示しても、独立した1属性の変更で他の行を再読取りしません。
接続・親属性・アニメーションによる変更も追従し、Undo／Redoや単位変更では全対象を再同期します。
選択が変わると古いBindingと連続編集を終了してから、新しい対象へ接続します。
タイトルバーのclose、`close()`、`dispose()`、tools reloadでもcallbackと入力を終了します。
モード・フィルター切替、選択変更による行の再構築とWindow終了では、開いている属性メニューと
enum・表示状態の選択肢も閉じ、古いBindingと連続編集を終了します。

```python
import bd_tools

bd_tools.reload_package()                 # toolsのみ変更した場合
bd_tools.reload_package(reload_util=True) # utilも変更した場合
```

## 実装の分担

`bd_channel_box/ui.py` は公開Windowと配置・reload、`widget.py` は名前欄・属性行・メニュー・検索条件、
`table.py` は属性選択・数値直接入力・検索行の表示切替、`controller.py` は基準node・対応属性・
選択追従と操作対象の組み立てを所有します。
controllerの`node_names`と`node_ids`はMayaの選択順を維持し、
`representative_node_name`はその末尾（未選択時は`None`）を返します。
名前欄のBindingは選択変更時に古い入力を終了します。改名・Undo／Redo・
モード／フィルター変更で属性行を再構築する際は、末尾nodeのUUIDが同じなら名前欄を維持します。
行の属性とフィルターは末尾の基準nodeで決め、Bindingと行の`target_names`だけを
「基準node、そのほかの対象を元の選択順」に並べます。utilの先頭plugを代表とする契約を
保ち、複数ノードのアニメーションカーブ対応には元の`node_names`順を使用します。
一覧は`QTableView`の1属性1セルで構成し、delegateのpersistent editorとして既存の行Widgetを
常時表示します。既存の数値・Step・Slider・bool・enum・string・状態ViewとBindingを維持し、
値をtable modelへ二重に保存しません。選択中の複数属性への文字入力だけ一時的な文字欄で受け付け、
既存Viewからの上下・Slider・bool・enum・string入力はutilの任意入力handlerを通してcontrollerへ渡します。
Step入力はWindow内で選択を解釈し、各行の既存Viewと`FloatStepProfile`へ反映します。
Windowはutilの `MayaDockableWindow` を継承し、`dock_closed` と
`dock_about_to_dispose` で入力controllerを終了します。workspaceControl作成・削除・
Maya再起動時の接続・画面外補正・配置resetはutilへ委譲します。
stepの初期値選択と保存対象の判定はtools、属性path・単位種別ごとのprofileと状態保存、
値とstepの連動はutilが所有します。
値の単位変換・型付き属性列挙・一括書込み・混在状態・Undoはutilを使用します。
接続属性の編集可否・Auto Key処理・値とキーの復旧もutilが所有し、toolsは数値・bool・enumの
BindingとPaste APIで`edit_connected=True`を指定して有効化します。
util側ではアニメーション付き属性を既定で表示専用に保ちます。
複数行の値操作はutilの`apply_plugs_values()`へ型付きの絶対値または相対値の編集要求を渡し、
全件の事前検証・復旧・1回のUndoを委譲します。Sliderは`MayaEditSession`も渡して連続入力をまとめます。
多数ノードの数値入力では、操作用Bindingの入力前同期を基準の編集可否確認へ限定し、
floatの単位換算はその時点のStoreの表示単位を使います。全対象の状態と値は適用後に同期します。
基準が編集不可の場合も除外理由を最新化し、通常の表示用Bindingの同期は維持します。
各対象の最新値・範囲・lock・接続の検証、書込み直前の再検証と削除履歴の確認はutilへ委譲します。
多数ノードの対象照合は`inspect_scalar_attribute_types()`で正式path・型だけを取得し、
基準ノード以外の表示名・表示フラグを読みません。同時に作る値Bindingは
`shared_plugs_lifetime()`内で生成し、削除通知をnodeごとに共有します。
各対象の削除履歴と各Bindingの検証・Undo・復旧は独立させ、購読者自身の終了だけを解除します。
対象キャッシュの再利用時には監視を作り直さず、通常の表示用Bindingは従来の監視を維持します。
カーブ貼付先の準備では値Bindingを作らず、選択行またはコピー曲線の候補pathだけを調べます。
leaf名が曖昧なnodeだけ全列挙へ戻し、既存の正式path一致による対象外判定を維持します。
曲線はコピー元node番号ごとに元の順で分類し、選択順の対応と一曲線の複数属性への展開を保ちます。
選択カーブのカット・削除も値Bindingを作らず、一属性だけならその正式pathだけを調べます。
曖昧名は全列挙へ戻して正式pathを比較し、複数属性は従来のnode内属性順で列挙します。
対象側の型が基準と異なる属性も、従来どおり各nodeの曲線操作可否で判定します。
多数ノードのキー・Layer・mute・lock・表示操作では、正式path・型・単位の照合と
対象名の準備を値Bindingの生成から分離します。値やenum定義の読取り・値監視は作らず、
各操作自身の接続・lock・状態変更可否の検証を維持します。enum定義が異なる対応先を
値編集の除外規則で落とさず、lock・表示の行ごとの基準属性の制約も維持します。
lock・表示の結果通知は、各状態操作の候補件数と除外理由を示します。
toolsは時刻変更で連続編集と未確定入力を終了し、値の読取りと同期は既存Bindingへ委譲します。
属性の表示・ロック状態の読取り、一括操作、Undo、操作可否と監視もutilが所有します。
値編集と状態編集の対象選別、モード・フィルター切替とWindow内の選択保持、
共通入力幅と各入力欄はtoolsが所有します。
状態変更による絞り込みはQtの次のイベントで行い、書込み中のBindingを破棄しません。
別ツールはこのcontrollerへ暗黙に依存せず、必要な汎用APIをutilから利用します。

### 拡張時に維持する仕様

- 選択・表示更新・外部からの値変更は読取りと表示同期だけにし、他ノードへ値を転送しない。
- 明示的な入力・揃える操作だけを一括編集し、Undoで各ノードの元値を復元する。
- ノード選択と属性選択を分け、属性選択・未編集のフォーカス移動では値を揃えない。
- 複数行の値操作は全対象を先に検証し、途中の失敗で一部の行だけ変更を残さない。
- Stepの変更はViewの操作設定として扱い、sceneとUndoへ書き込まない。
- モード・フィルター切替では値・状態・Undoを変更せず、入力幅とstep設定を維持する。
- 表示状態とロックを独立して変更し、非表示属性も状態モードから復帰できるようにする。
- なぞり操作は1回のUndoへまとめ、フィルターによる行の除去は操作終了後に反映する。
  選択・scene・属性構成が変わる場合は、なぞりを終了して古い対象を解放する。
- 編集不可属性や型・範囲の不一致を尊重し、除外理由や拒否理由を表示する。
- 選択切替・close・reloadでは古い入力、連続編集、callback、メニューを確実に終了する。
- 汎用の型・Binding・View・保存基盤はutil、表示対象と各行の組み合わせはtoolsへ置く。

### 値編集の対象構築

`Mode: 値編集`（`values`）は先頭・初期選択の値編集モードです。
従来の多数ノード版の方式へ一本化し、少数から1,000以上まで同じ仕様で操作します。
属性フィルター・検索・値・Step・Slider・右クリックメニューは維持します。
表示属性・値・接続色・ロック状態は、選択末尾の基準ノードだけから取得します。
選択ノード数は全件を表示しますが、値や接続状態の混在、全対象の編集可能件数は
常時計算しません。基準ノードの状態を全ノード共通の状態と解釈しないでください。

値の明示入力・整列・Pasteなどの操作時に、操作する属性だけを選択中の各ノードから
解決します。同じ正式path・型・単位を持つ属性を対象とし、enumでは定義も確認します。
属性の欠落・型の違い・lock・未対応接続は既存の操作方針で判定します。
対応属性のhard limit違反など、全件検証で拒否する条件は一部の行へ適用を残しません。
基準と同じ値を明示入力した場合も、異なる値を持つ他ノードへ適用します。
外部の値変更、選択変更、表示更新、Step変更だけでは一括適用しません。

数値・bool・enum・string入力と選択属性の丸めでは、選択キー全体を先に検証し、
操作する型の行だけを全ノードへ結びます。非対応型の値やenum定義は操作のために
読み直さず、行単位で対象外の理由を報告します。適用候補は操作する型の編集可能件数です。
例えば1000ノードで数値3行と非数値5行を選んで数値操作した場合、候補は8000属性ではなく
3000属性で、非対応型は5行分を報告します。候補は変更件数ではなく、同値の対象も含みます。
フィルター対象の揃え・丸めでも、表示条件と表示名は基準から取得し、他ノードは正式pathと
型だけを照合します。丸めはfloat系だけを準備し、整数・bool・enum・stringは行単位で除外します。
揃えは同値行を再適用せず、基準値・属性順・後続のlockとhard limitの検証を維持します。
選択カーブCopyは値編集用Bindingを作らず、曲線に必要な対象名だけを取得します。
enum定義が異なる対応先も従来どおり曲線コピーに含め、lockによるコピー可否はMayaの規則を使います。
元のノード選択順と曲線・属性の対応を保ち、値入力時のenum定義の一致規則は変更しません。

このモードのenum明示入力、選択属性・フィルター対象の値揃え、値Pasteは、utilの
`enum_validation="operation"`を使用します。一括入力へ渡した全enum対象の整数値と
項目名の定義を開始時に新しく取得して固定し、各書込み直前にその行の基準と当該対象、
終了時に全行の全対象を確認します。lockや同値により書き込まなかった対象も終了確認に
含みます。全員が同じ新定義へ変わった場合も、開始時と違えばエラーにします。
後続・既適用・未書込み対象や別行の定義変更は、終了時の確認で発見する場合があります。
終了確認も同じUndo／復旧処理内で行い、失敗時は今回の値とキーの復旧を試みます。
外部callbackの副作用や定義自体は復旧対象外で、復旧できない場合もエラーを通知します。
値Pasteの事前除外規則と、アニメーションカーブの
Paste経路は変更しません。

Sliderは従来どおりドラッグ中に全対象へライブ入力し、一連の操作を一回のUndoへまとめます。
押下から解放まで全対象の照合と一時Bindingを再利用します。
各入力の現在値・lock・範囲・接続は新しく確認し、復旧値と書込み計画も毎回作り直します。
全選択nodeの属性追加・削除・改名とnodeの改名・削除を監視し、構成変更後の入力は拒否して
ドラッグを終了します。APIから別の属性keysを指定した場合は、その入力で対象行を解決し直します。
画面の属性行選択・node選択・モード・フィルター・時刻・画面の変更、入力失敗、解放では
連続入力を終了し、一時対象と監視を解除します。
値欄のwheel・上下操作とSlider上のwheelは、一イベント一Undoを維持します。
最初の単発入力は対象を保持せず、同じ属性への次の数値入力が
処理終了後500ms以内に続いた場合に、対象の照合と一時Bindingを再利用します。
保持するのは対象だけで、現在値・表示単位・Step・lock・範囲・接続と復旧値は毎回確認します。
値欄では各nodeの現在値に同じ表示差分を加え、Sliderでは基準値へ揃える規則を維持します。
入力が途切れた場合、属性行・選択node・モード・フィルター・時刻・画面の変更、
Undo／Redo、別種の操作、入力失敗では、待機中の対象と監視も解放します。
イベント間の属性構成変更は旧対象を破棄し、新しい操作として現在の実体を解決します。
書込み中に削除して同名再作成された属性は旧対象へ追従せず、残る対象の値を復旧します。
一時Bindingでは表示用のキー状態取得だけを省き、基準の状態表示と接続検証は維持します。
選択変更・時刻変更・close・reloadでは連続編集と古い入力を終了します。
入力の確定ごとに全対象の検証と書込みを行うため、実際の書込みやscene評価に必要な時間は
ノード数・接続・キー数に応じて増えます。常時表示を軽くするモードであり、
大量のアニメーション付きノードに対するSliderの一定速度を保証するものではありません。

右クリック操作の対象範囲も従来どおりです。値Copyとノード名変更は基準一個、
値の整列・Paste・選択属性のlock・表示状態・キー操作は対応する全選択ノードを扱います。
「回転をセット（姿勢を維持）」「移動・回転をセット（子を維持）」は独立ツールを開き、
各ツールが従来どおり基準一個を対象にします。値編集の一本化でも対象範囲は維持します。

全対象を常時計算していた旧通常版は廃止し、値の混在を示す「•」や全対象の混在情報は表示しません。
表示・ロックも選択数上限はなく、基準の常設表示と操作時の全対象解決へ分離します。
呼出し側は`controller.set_mode("values")`を使用します。旧`bulk_values`は削除しました。
`AttributeRowWidget`も基準表示へ統一し、旧`representative_only`引数の指定は削除します。
Mode自体はWindow内で保持し、値編集のフィルター選択だけを個人設定へ保存します。
このモード統合に伴うscene・保存設定の移行は不要です。

### 多数ノード対応の完了記録と開発引き継ぎ

2026-10-22に利用者から最新実装の動作確認・push完了の報告を受けました。
今回の多数ノード対応は開発完了とし、追加の高速化は具体的な負荷や不具合の報告が
あった場合に再開します。全モードの選択数上限はなく、少数から多数まで同じ入口を使います。

| モード | 常時表示・監視 | 明示操作の対象 |
| --- | --- | --- |
| 値編集 | 末尾の基準ノード一個 | 対応する全選択ノードの属性 |
| 表示・ロック | 基準一個の表示フラグ・自身のlock | 対応する全選択ノードの属性 |
| カスタムフィルター設定 | 基準一個の属性候補 | 基準のノード型に対する共有JSONの作業中データ |

値編集と表示・ロックは全選択の名前・実体・DAG経路を操作対象として保持します。
選択取得や識別情報の準備も含めて一定時間になる設計ではありません。
フィルター設定だけは基準一個を保持し、他モードへ戻るとMayaの全選択を取得し直します。
この区別を、すべてのモードが基準ノード一個だけを編集する仕様へ変えないでください。

保守時は次を維持します。

- 表示は全員の一致状態を表しません。混在や全対象の変更可能件数を常時集計せず、
  対応属性と可否・除外理由を操作時に確認します。適用候補数は実際の変更件数とは異なります。
- 画面に常設する`ChannelRow.binding`、`ChannelStateRow.state_binding`と`target_names`は
  表示用の基準だけです。
  全対象への入力はcontrollerの明示操作入口を使い、表示Bindingへ直接入力して代用しません。
- 同じ表示値・状態への明示入力も、他の対象に差分があれば適用します。
  表示更新・外部変更・Step変更だけでは他ノードへ書き戻しません。
- 値用と状態用の操作可否を混同しません。状態編集は自身のlock解除や接続済み属性の
  表示変更を扱い、enumの項目定義が違っても正式path・型区分が対応すれば対象にします。
  値編集のenum定義・範囲・接続の検証は従来どおり行います。
- 通常の状態クリックは選択属性全体、なぞりは開始列の実際に通過した行だけへ適用します。
  未通過の選択行は変えず、同じ行は一ドラッグ一回です。基準が同状態でも入力要求を省きません。
  lockは基準のOFFから全対象をロック、ONから全対象を解除します。
- 単発の複数属性入力は一つの適用処理へ集約して一括復旧します。状態なぞりは行ごとに
  即時適用し、失敗した行を復旧して先行成功行は保持します。共有セッションはなぞり全体を
  一回Undoへまとめるもので、全行の自動復旧を行う仕組みではありません。
- なぞり中はフィルターによる行の再構築を保留し、選択・構成・sceneの変更やclose／reloadで
  古い入力を終了します。フィルター設定のなぞりはdraftだけを変更し、radioを即時同期、
  表示順などを終了時に更新します。Mayaの値・フラグ・Undo・保存済みJSONには触れません。
- 再利用は既存の操作範囲に限定します。削除と同名再作成を区別し、型・値・lock・範囲・
  接続・enum定義の確認や例外時の解放を、速さのために省きません。状態の一時Bindingも
  操作終了時に監視を破棄し、行数×ノード数の常設監視へ戻さないでください。

toolsはMaya 2025／2026／2027の全runtime test各594件、unit 38件、3版の型検査と整形を
確認済みです。utilの公式検証と、Maya 2025本体の1000ノード操作を含む15段階の成功結果も
[検証記録](testing.md#性能比較を記録するとき)に残しています。
利用者の動作確認は完了していますが、任意の実rig・大量キー・SDK・Layerを含むすべてのsceneや、
1000を大きく超える選択数で一定の応答時間を保証するものではありません。

検証用Mayaの終了待ちタイムアウトは、操作成功と分けた保守課題です。
最新の15段階はsuccess=true／error=nullですが、終了待ちでrunnerは終了code 1でした。
正常終了と原因の確認は未完了のまま記録し、今回の機能対応完了を終了問題の解消とは扱いません。

全選択対象を照合する処理を減らします。登録するcallback本数は維持し、削除済み対象の
扱い、親lockなどの検証、Undo、途中失敗の復旧は変更しません。

値Pasteでは、utilが対象ごとの表示用BindingとViewModelの生成を省きます。
各対象の独立した一時Storeから通常入力と共通の検証・書込み処理を使い、
対象件数・除外理由、enum検証、一回Undoと失敗復旧を維持します。
一時Storeは代表と対象が同一のため、同じ段階内のenum定義・値の重複確認を省き、
直後の共通書込み処理で検証します。開始・書込み前・同値対象も含む終了検証は残します。
貼り付け対象が複数属性の場合は、候補Storeの構築中だけnode情報も共有します。
指定pathへの絞込み・一値の複数path展開後の属性数で判断し、単一属性は従来の経路を使います。
書込み計画の準備前に共有範囲を閉じ、初期除外・要求順・検証・復旧処理を変更しません。
操作中の対象削除を記録し、同名で再作成された別node・属性へ追従しません。
外部処理による削除・再作成自体は復旧対象外で、値を復旧できない場合はエラーにします。
UI・メニュー・公開API・scene・保存設定は変更しません。

多数ノードの複数行を同時に構築する間は、utilの`shared_scalar_plug_nodes()`で
同じnodeの操作オブジェクトを共有します。名前と実体・DAG経路は毎回解決し、
経路変更時は以後のwrapperだけを作り直します。属性の正式path・型は毎回照合します。
索引は構築終了・例外時に解放し、操作をまたいだnode情報や属性・値のcacheは追加しません。
既存の連続数値入力用Bindingの再利用範囲・検証・Undoは変更しません。
値編集のフィルター対象の揃え・丸めでも、選別後の複数行を構築する間だけ
同じ共有を使います。単一行は従来の構築経路を使用します。
適用前に共有範囲を閉じ、揃えの混在判定、同値で範囲外になった行の非再適用、
型・範囲・lock・enum定義の検証と、丸めの対応型・候補報告は維持します。

行再構築では編集メニューの有効性だけを更新し、Paste説明文のためにclipboardを全解析しません。
編集メニュー・行メニューの表示時に最新内容から説明文を更新します。
Paste実行時は改めて全内容を読み検証し、メニュー表示時の判定は使い回しません。

enumの一括入力では、utilが`MPlug.attribute()`の`MObject`実体を共有する対象をまとめ、
検証のたびに各共有定義を新しく取得して比較します。`drawStyle`など、同じ標準属性を
多数ノードで編集するときの重複取得を削減します。標準／動的の区別で定義を不変とは扱わず、
同名・同内容でも別実体のカスタムenumはまとめません。全ノードが別実体ならこの削減は効きません。
定義変更の検出、Undo、途中失敗の復旧と、UI・右クリックメニューの仕様は維持します。
値編集では、上記の操作単位の検証方式も併用し、別実体のカスタムenumに対する
全件取得の繰り返しを減らします。定義確認は毎回の新しい解析で行い、文字列署名や
min/maxだけで省略しません。検証方式の変更による発見時期と復旧範囲は上記のとおりです。

値変更の同期と選択変更による行の再構築は、別の処理として計測します。
値変更では無関係な行の再読取りを避け、選択変更では古い入力とcallbackの解放を維持します。
値編集・表示とロックは基準だけの常設Bindingと、
操作時の一時的な全対象解決へ分け、表示のために全対象を調べる処理を省きます。
追加のcache・行再利用・監視共有は、負荷計測で必要性が確認された場合に、
無効化条件とlifecycleを含めて検討します。
選択数上限はありませんが、処理時間を保証するものではありません。従来の値編集の反復
選択切替benchmarkは最大10ノードです。最新の専用stageは1000ノードの状態操作・設定切替も
確認しますが、一般のrigや全入力方式に対する反復性能保証には使用しません。
